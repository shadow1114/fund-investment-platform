## 2. 成本构成（已定案）

> **沿用 `02-business-requirements` §21.7。成本组成必须逐项明确，尤其要避免重复计费。**

| 成本项 | `included_in_nav` | 是否在回测中扣除 | 说明 |
|---|:---:|:---:|---|
| **申购费（Subscription Fee）** | ❌ | ✅ **扣除** | 交易时发生 |
| **赎回费（Redemption Fee）** | ❌ | ✅ **扣除** | 交易时发生，**可能含持有期惩罚** |
| **管理费（Management Fee）** | ✅ | ❌ **不扣除** | **已反映在基金净值中** |
| **托管费（Custody Fee）** | ✅ | ❌ **不扣除** | **已反映在基金净值中** |
| **销售服务费** | **`UNKNOWN`**（`OPEN-19`） | ❌ 不扣除，**但须列入 `unmodeled_costs`** | 见 §2.1 |
| **ETF 买卖价差（Bid-Ask Spread）** | ❌ | ✅ 扣除 | 场内交易成本 |
| **市场冲击成本（Market Impact）** | ❌ | ✅ 扣除 | 大额交易时显著 |
| 税费 | ❌ | `TBD` | 视市场与账户类型 |

### 2.1 「是否扣除」是推导结果而非独立配置（v1.1 定案）

> **定案 · 2026-08-27**：`TBD-TC-8` 关闭。见 `02-business-requirements` §21.7.1、`TBD-resolution.md` Policy ⑩。

```
included_in_backtest = NOT included_in_nav AND 该费用在交易时发生
```

**本域不再自行判定某项费用扣不扣** —— 它由 `03-data` 提供的 `included_in_nav` 与「是否在交易时发生」共同推导。上表第二列是数据，第三列是结论。

**三值 `included_in_nav` 对应的三种处置**：

| `included_in_nav` | 回测处置 | 报告处置 |
|---|---|---|
| `TRUE` | **不扣除** | 无需特别说明 —— 成本已在净值收益里 |
| `FALSE` | **扣除** | 计入 `cost_by_type` |
| **`UNKNOWN`** | **不扣除** | **必须列入 `unmodeled_costs` 并在报告显式披露** |

> **`UNKNOWN` 的处置是不保守的，这是有意的选择**：另一个方向（默认扣除）会在费用其实已含于净值时造成重复扣费 —— 那是**双重错误**，既低估表现，又因为看起来"成本模型很完整"而不会被察觉。不扣除至少是**单一且已披露**的偏差，调用方能从 `unmodeled_costs` 看到它。

> **`UNKNOWN` 不是"暂时状态"** —— 若某数据源永远不声明包含关系，该费用会长期停留在 `UNKNOWN`。这不影响回测可执行性，但**该基金的成本模型完整度须在报告中降级标注**（§17）。

## 3. 管理费与托管费不得重复扣除 ⚠️

> **这是本域最重要的一条约束。**

```
管理费与托管费已内含于基金净值 —— 这是基金产品的基本事实

若在净值收益之上再扣一次管理费
    → 会系统性【低估】策略表现约 1–2% 年化
```

（`02-business-requirements` §21.7）

### 3.1 这是一个方向相反但同样严重的错误

> **前视偏差与幸存者偏差会高估表现，重复扣费会低估表现。**

| 错误 | 方向 | 后果 |
|---|---|---|
| 前视 / 幸存者偏差 | **高估** | 策略看起来比实际好 → 上线后不及预期 |
| **重复扣费** | **低估** | 有效策略被误判为无效 → **被错误否决** |

> **低估的后果同样严重** —— 一个真实年化超额 1.5% 的策略，若被重复扣掉 1.5% 管理费，会显示为零超额而被淘汰。

### 3.2 数据侧的对应约束

> `03-data/05-data-normalization` §6 已明确：**"管理费与托管费已含于净值，不再扣除；申赎费属交易成本，由 `08-backtest` 处理"**。

**两处必须一致** —— 若数据侧提供的是"费前净值"，本域的扣除规则必须相应调整。

> **定案后这一致性由字段保证而非文档约定**（§2.1）：本域读 `03-data` 的 `included_in_nav`，两侧不可能不一致。若数据源改为提供费前净值，`03-data` 把管理费的 `included_in_nav` 改为 `FALSE`，本域自动开始扣除 —— 无需修改本域任何规则。

`<TBD-TC-1: 确认数据源提供的净值是否已扣管理费与托管费，待数据确认 —— 与 `OPEN-19` 同源，均属数据侧核实>`

### 3.3 费率也是评分因子，第三处不得重复

> **费率在 `04-factor` / `05-fund-evaluation` 中作为评分项**（`02-business-requirements` §14.3 读表规则 4，Preference Direction = `LOWER_IS_BETTER`）。

```
费率的三处出现：
  ① 基金净值中（管理费/托管费已扣）      —— 事实
  ② 评分因子（费率低者得分高）           —— 评价
  ③ 回测成本（申赎费）                   —— 交易

三者【不冲突】，因为扣的不是同一笔：
  ① 是持有成本，已在净值里
  ② 不扣钱，只影响选基
  ③ 是交易成本，只在买卖时发生
```

> **需要澄清是因为容易被误认为重复** —— 实际上只有 ① 与"回测再扣管理费"才是重复。

## 4. 基金特有的成本项

### 4.1 申购费

```
申购成本 = 申购金额 × 申购费率
```

| 要点 | 说明 |
|---|---|
| 费率来源 | `03-data`（`Fund Fee`） |
| **费率分档** | 通常按申购金额分档，大额费率更低 |
| **份额类别差异** | A 类通常有申购费，C 类通常无 |

### 4.2 赎回费与持有期阶梯 ⚠️

> **这是基金组合与股票组合的核心差异**（沿用 `06-portfolio/06` §7.2）。

```
赎回费率 = f(持有期)

典型阶梯：持有 < 7 天  → 惩罚性费率（如 1.5%）
          持有 < 30 天 → 较高费率
          持有 ≥ 1 年  → 0
```

### 4.3 持有期依赖使成本成为路径函数

```
股票：交易成本 ≈ f(交易量)
基金：赎回费    = f(交易量, 持有期)
    → 同样卖出 5%，持有 6 天与持有 60 天的成本可能相差数倍
```

**三个后果**：

| # | 后果 |
|---|---|
| 1 | 成本计算需要**持仓的买入批次**，而非仅当前权重 |
| 2 | **"先进先出"还是"后进先出"的批次选择会改变成本** |
| 3 | 频繁调仓的成本远高于按平均费率的估算 |

### 4.4 批次选择规则必须显式定义

```
Lot Selection Rule = TBD
```

| 规则 | 效果 |
|---|---|
| **FIFO（先进先出）** | 优先卖出持有最久的份额 → **赎回费最低** |
| **LIFO（后进先出）** | 优先卖出最新买入的份额 → 赎回费可能最高 |
| **最优成本** | 主动选择费率最低的批次 | 

> **FIFO 与"最优成本"在赎回费阶梯下往往一致**，但在有其他约束（如税费批次）时可能不同。

> **已定案 · 2026-08-27**：批次选择规则 = **FIFO**（先进先出）。
>
> **依据**：赎回费按**持有期阶梯**（`TC-3`），FIFO 使最早买入的份额先被赎回，**适用最低费率** —— 这与实际操作中的理性选择一致（投资者会优先赎回已过惩罚期的份额），也与多数基金公司的默认规则一致。
>
> **LIFO 会系统性高估成本**：最新买入的份额持有期最短，费率最高。用 LIFO 等于假设投资者总是做出最不利的选择。
>
> **须与 `DBD-5` 的 `position_lot` 表配合** —— FIFO 需要逐批次记录买入时点与份额，这正是该表存在的理由。

### 4.5 批次跟踪使 Portfolio State 变复杂

> **沿用 `01-backtest-engine` §11：维护份额而非权重。若要建模赎回费阶梯，还须维护逐批次的买入日期与份额。**

```
Portfolio State 中每只基金的持仓 = [(买入日期, 份额), ...]
    → 而非单一的"持有 X 份"
```

**第一阶段是否建模批次待确认** —— 若不建模，必须在报告中声明这一简化（§12.2）。

> **已定案 · 2026-08-27**：第一阶段**建模赎回费的持有期阶梯**。
>
> **依据 —— 忽略它会系统性低估高换手策略的成本**：
>
> ```
> 典型阶梯：持有 < 7 天收 1.5%，7~30 天 0.75%，30 天~1 年 0.5%，> 1 年 0
>
> 用单一费率（如 0.5%）近似
>     → 季度调仓策略：多数份额持有 90 天，实际 0.5% —— 近似准确
>     → 月度调仓策略：多数份额持有 30 天，实际 0.75% —— 低估 50%
>     → 且【换手越高，低估越严重】
> ```
>
> **这个偏差的方向使高换手策略看起来更好**，恰好是最需要被准确评估的那类策略。
>
> **代价**：成本成为**路径函数**（`06-portfolio/06` §7.2）—— 同一笔赎回的成本取决于建仓时点，因此回测必须逐批次跟踪持仓。这是 `DBD-5` 建 `position_lot` 表的直接原因。

## 5. Slippage

```
Slippage = |实际成交价 − 观察价| / 观察价
```

```
Slippage Model = TBD
```

### 5.1 基金申赎的滑点与股票不同

> **开放式基金按净值申赎，理论上无滑点。**

| 品种 | 滑点来源 |
|---|---|
| **开放式基金（场外申赎）** | **理论上无滑点** —— 按确认日净值成交 |
| **ETF / LOF（场内交易）** | 有 —— 买卖价差与冲击成本 |
| 大额申赎 | 可能触发**巨额赎回条款**，导致延期或部分确认 |

### 5.2 真正的"滑点"是时点滑点，不是价格滑点 ⚠️

```
决策在 T，成交按 T+1 净值
    → T 与 T+1 之间的净值变动就是实际的"滑点"
    → 它不是执行质量问题，是时滞的固有结果
```

**这一项已由 `01-backtest-engine` §10 的执行价格规则覆盖** —— 本域不重复建模。

> **已定案 · 2026-08-27**：第一阶段**不引入额外滑点模型**。
>
> **依据 —— 场外基金按净值申赎，不存在滑点**：滑点是「预期成交价与实际成交价的差异」，而基金申赎按当日净值确认，价格是确定的。
>
> **ETF 的场内交易确实有滑点**，但该部分已由 **Bid-Ask 价差**（`TC-5`）与**市场冲击成本**两项覆盖 —— 再加一个滑点模型会重复计算。
>
> **将来引入的前提**：需要区分「场内交易的 ETF」与「场外申赎的基金」两条成本路径，且需要 ETF 的分笔成交数据。

## 6. Spread

```
Spread Cost = 交易金额 × (Bid-Ask Spread / 2)
```

> **仅适用于场内交易品种（ETF / LOF）。** 场外申赎无价差。

### 6.1 数据前提

> 需要 Bid / Ask 数据，而 `03-data` 当前的 Dataset 清单中**没有该数据**。

**因此**：若 Universe 含场内品种，价差成本第一阶段**不可建模**，须在报告中声明。

> **已定案 · 2026-08-27**：第一阶段**不引入 Bid/Ask 数据**；价差成本列入 **`unmodeled_costs`** 并披露。
>
> **依据**：Bid/Ask 数据属 `03-data` 的扩展（新增 Dataset、新增 Provider 接入），不在第一阶段范围。
>
> **不建模不等于假装没有** —— 价差成本明确列入 `unmodeled_costs`，与市场冲击、销售服务费（`UNKNOWN` 状态）并列。**回测报告中的成本因此是一个已知的下界**，这一点必须在报告中呈现（`10-api/05` §4.9.1）。
>
> **影响范围有限**：第一阶段的 Universe 以场外基金为主，ETF 占比低时价差成本的绝对量级较小。若将来 ETF 占比上升，本项须重新评估。

## 8. Transaction Cost Formula

### 8.1 概念公式

```
Transaction Cost
    = 申购成本（买入侧）
    + 赎回成本（卖出侧，含持有期阶梯）
    + 价差成本（场内品种）
    + 冲击成本（若建模）
    + 其他适用成本（销售服务费、税费等）
```

### 8.2 逐笔计算

```
对每一笔交易：
  买入：cost = 买入金额 × 申购费率(金额档位)
  卖出：cost = Σ_批次 (该批次卖出金额 × 赎回费率(该批次持有期))
```

> **卖出成本必须逐批次计算**（§4.3），不能用单一费率乘总额。

## 9. Turnover

> **复用 `06-portfolio/06-rebalancing` §6 的定义，本域不重新定义。**

```
Turnover = 0.5 × Σ |w_target − w_current|
```

### 9.1 单边口径（已定案）

> **沿用 `06-portfolio/06` §6.2：本项目采用单边口径（带 0.5 系数）。**

```
不带 0.5：计入买卖两侧 → 全部换掉 = 200%
带 0.5：  单边换手     → 全部换掉 = 100%
```

> **口径必须显式声明** —— 两种口径相差一倍，直接改变成本侵蚀比例的含义。

### 9.2 Turnover 与成本不是线性关系 ⚠️

> **容易被误认为"成本 = 换手率 × 平均费率"。**

```
同样 20% 的换手：
  情形 A：卖出持有 3 年的基金 → 赎回费 0
  情形 B：卖出持有 10 天的基金 → 惩罚性赎回费
    → 成本相差数倍，换手率相同
```

**因此换手率是成本的粗略代理，不能替代逐笔计算。**

### 9.3 冻结持仓不计入换手率

> 沿用 `06-portfolio/06` §6.4：`NOT_TRADABLE` 的权重差异无法交易，计入会虚增换手。

## 10. Gross Return vs Net Return

### 10.1 计算链

```
Gross Portfolio Return   （不含交易成本）
        ↓  扣除 Transaction Cost
Net Portfolio Return     （回测的实际绩效）
```

### 10.2 两者不可混淆

| | Gross Return | Net Return |
|---|---|---|
| 含义 | 策略的**理论**表现 | 策略的**可实现**表现 |
| 用于 | 分解成本影响 | **全部绩效判定与三方对比** |
| 报告 | 须同时呈现 | 须同时呈现 |

> **全部绩效指标、三方对比、统计判定均基于 Net Return**（`02-backtest-methodology` §7、§9）。Gross 仅用于成本归因。

### 10.3 成本侵蚀比例

```
成本侵蚀比例 = (Gross Return − Net Return) / |Gross Return|
```

> 它是 `02-business-requirements` §22.1 第 7 项"换手率是否过高"的判断依据之一。

### 10.4 等权基线也必须计成本

> **沿用 `02-backtest-methodology` §7.3：用零成本的等权基线对比含成本的策略，会人为抬高策略的相对表现。**

## 11. Cost Timing

```
Cost Timing = TBD
```

| 候选 | 说明 |
|---|---|
| **Trade Date** | 交易发生日计入 |
| **Execution Date** | 成交确认日计入 |
| **Settlement Date** | 资金清算日计入 |

### 11.1 时点选择影响净值序列的形状，不影响总量

```
成本总额相同，但计入时点不同
    → 净值曲线的短期形状不同
    → 若成本较大，可能改变某一期的收益符号
    → 进而影响"跑赢概率"（02-backtest-methodology §9.3.2）
```

> **这是一处容易被认为"无所谓"实则有影响的选择。**

> **已定案 · 2026-08-27**：成本计入时点 = **交易发生日**（非结算日）。
>
> **依据 —— 与净值序列的时点保持一致**：
>
> ```
> 交易发生日：T 日调仓，成本计入 T 日
> 结算日：    T 日调仓，资金 T+2 到账，成本计入 T+2
>
> 若用结算日
>     → 成本与它对应的持仓变动【错期】
>     → T 日的组合净值反映了新持仓，但未反映为此付出的成本
>     → 净值曲线在 T 日虚高，T+2 日虚低
> ```
>
> **错期不改变总成本，但改变净值曲线的形状** —— 而波动率、最大回撤这些指标恰恰依赖曲线形状。
>
> **申赎确认时滞（`BE-4`）与成本计入时点是两件事**：前者决定持仓何时变化，后者决定成本何时扣减。两者都以「交易发生日」为基准，保持一致。

## 13. Cost Sensitivity

> **框架预留，第一阶段是否实现待定。**

| 情景 | 说明 |
|---|---|
| **Base Cost** | 基准假设 |
| **Low Cost** | 乐观假设 |
| **High Cost** | 保守假设 |

### 13.1 敏感性分析的价值在于识别"成本脆弱"的策略

```
策略 A：Base 下年化超额 3%，High Cost 下 2.5%   → 稳健
策略 B：Base 下年化超额 3%，High Cost 下 0.2%   → 成本脆弱
    → B 的超额收益几乎全部来自成本假设
```

> **高换手策略尤其需要该分析** —— 它们对成本假设最敏感。

> **已定案 · 2026-08-27**：第一阶段**不实现成本敏感性分析**。
>
> **依据 —— 对未定参数做敏感性分析没有意义**：成本模型自身的费率取值仍待数据（`RE-5`、`TC-1`、`OPEN-19`）。在基准值都未确定时，「成本上浮 50% 会怎样」的分析缺乏参照点。
>
> **正确的顺序**：先确定费率的真实取值 → 再评估结论对该取值的敏感度。反过来做，敏感性分析会变成对一组假设值的假设分析。
>
> **将来实现时的建议三档**：实际费率、上浮 50%、下调 50% —— 用于回答「若费率环境变化，结论是否翻转」。

## 14. No Double Counting

### 14.1 三项必检

| # | 检查 |
|---|---|
| 1 | **管理费/托管费未在净值之外再扣**（§3） |
| 2 | 同一笔交易的成本未被多次计入 |
| 3 | 买入与卖出的成本未因换手率的双边/单边口径混淆而重复（§9.1） |

### 14.2 自检恒等式

```
Σ 逐笔成本 == 累计 Transaction Cost
Gross Value − Σ 逐笔成本 == Net Value
```

> **不成立即说明存在重复计入或遗漏**，必须阻断。

## 17. Edge Cases

| 情形 | 处理 |
|---|---|
| 某基金费率数据缺失 | **不得默认为 0** —— 见 §17.1 |
| 买入金额恰在费率档位边界 | 按 Policy 明确的边界符号（`≥` 或 `>`） |
| 持有期恰在阶梯边界 | 同上 |
| 卖出份额跨多个批次 | 逐批次计算并汇总（§8.2） |
| 首期建仓 | 只有买入侧成本；换手率 50%（单边） |
| 冻结持仓（`NOT_TRADABLE`） | 无交易，无成本，不计入换手 |
| 部分成交 | 按实际成交金额计成本 |
| 基金清盘导致的被动退出 | 是否计赎回费按 `TBD-SB-1` |
| Gross 与 Net 差额与逐笔成本之和不符 | **`FAIL`** —— 存在重复计入或遗漏（§14.2） |

### 17.1 费率缺失不得默认为 0 ⚠️

> **与全平台"缺失不得转 0"是同一条原则。**

```
❌ 某基金无费率数据 → 按 0 计 → 该基金的交易"免费"
   → 优化器与调仓判据会系统性偏好数据缺失的基金
   → 且成本被低估，策略表现被高估
```

**正确处理**：该基金标 `INSUFFICIENT_DATA`，本期不参与交易；或整个回测标 `WARNING` 并在报告中列出。

## 19. Reproducibility

```
逐笔交易明细（含批次）
+ Transaction Cost Policy Version（费率、档位、阶梯）
+ lot_selection_rule
+ cost_timing
        ↓
    相同的逐笔成本与累计成本
```

### 19.1 费率数据的历史版本必须可查

> **费率会调整。** 若只保存当前费率，历史回测的成本无法复现。

```
2022 年该基金申购费 1.5%，2024 年降至 1.0%
    → 回测 2022 年的交易必须用 1.5%
    → 用今天的 1.0% 是【费率的版本前视】（03 §6）
```

**要求**：`Fund Fee` 必须按 PIT 取用（`03-data/02-data-domain-model` §8）—— 这是本域容易被忽略的一处 PIT 要求。

### 19.2 批次记录不可变

> 赎回费依赖持有期，而持有期依赖买入批次。批次记录若被重建或覆盖，历史成本不可复现（与 `01` §22.1 同源）。

## 20. Summary

本域定义的成本模型**回测与实盘共用**，回应 `06-portfolio/06` 的 `Transaction Cost Model = TBD`。

一条最重要的约束：**管理费与托管费已内含于净值，不得再扣**

- 重复扣除会系统性**低估**表现约 1–2% 年化
- 这是与前视/幸存者偏差**方向相反**但同样严重的错误 —— 一个真实年化超额 1.5% 的策略会被显示为零超额而**被错误否决**
- 费率的三处出现（净值中已扣 / 评分因子 / 交易成本）**不冲突**，因为扣的不是同一笔

三处基金特有的复杂性：

- **赎回费的持有期阶梯使成本成为路径函数** —— 需要持仓的**买入批次**而非仅当前权重；批次选择规则（FIFO/LIFO）会改变成本
- **真正的"滑点"是时点滑点** —— 开放式基金按净值申赎理论上无价格滑点，实际差异来自决策日与成交日之间的净值变动，已由执行价格规则覆盖
- **场外申赎的冲击体现为净值稀释而非成交价偏离** —— 不体现在交易记录中，因此很难单独建模

两处易被误认的关系：

- **Turnover 与成本不是线性关系** —— 同样 20% 换手，卖出持有 3 年与持有 10 天的基金成本相差数倍；换手率是粗略代理，不能替代逐笔计算
- **成本计入时点不影响总量但影响净值曲线形状** —— 可能改变某期收益符号，进而影响"跑赢概率"判定

两条不可省略的声明：

- **未建模的成本项必须显式列出** —— 未声明的简化等于回测高估了表现而读者不知情；上游明确"未声明处理方式的回测结果不得作为决策依据"
- **费率缺失不得默认为 0** —— 否则优化器会系统性偏好数据缺失的基金

## 21. Decisions

| # | 决策 | 理由 |
|---|---|---|
| D-1 | **管理费与托管费不扣除** | 已含于净值；重复扣会低估 1–2% 年化 |
| D-2 | 澄清费率三处出现不构成重复 | 扣的不是同一笔 |
| D-3 | 成本模型**回测与实盘共用** | 单一策略实现原则 |
| D-4 | **赎回费按持有期阶梯逐批次计算** | 成本是路径函数 |
| D-5 | **批次选择规则必须显式定义** | FIFO/LIFO 会改变成本 |
| D-6 | 不单独建模场外申赎的滑点 | 按净值成交理论上无价格滑点 |
| D-7 | 时点滑点由执行价格规则覆盖，本域不重复 | `01-backtest-engine` §10 |
| D-8 | **市场冲击第一阶段不建模**，通过规模约束间接控制 | 缺数据与理论模型 |
| D-9 | Turnover 复用 `06-portfolio/06` 的单边口径 | 避免重复定义 |
| D-10 | **全部绩效判定基于 Net Return** | Gross 仅用于成本归因 |
| D-11 | **等权基线同样计成本** | 否则人为抬高策略相对表现 |
| D-12 | **未建模成本必须显式列出** | 上游：未声明的回测不得作为决策依据 |
| D-13 | **费率缺失不得默认为 0** | 会系统性偏好数据缺失的基金 |
| D-14 | 设立 No Double Counting 自检恒等式 | 重复计入或遗漏必须被发现 |
