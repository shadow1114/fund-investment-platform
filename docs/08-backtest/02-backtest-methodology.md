## 2. Backtest Objective

### 2.1 回测验证的是"规则"，不是"结果"

> **沿用 `02-business-requirements` §21.1：验证基金筛选、评分与组合构建规则在历史数据上的有效性。**

```
回测【不是】证明未来收益能复制
回测【不是】参数搜索工具
```

### 2.2 可被验证的环节

| 环节 | 说明 |
|---|---|
| Fund Selection | Universe 构成规则是否有效 |
| Fund Evaluation / Scoring | 评分是否有区分度 |
| Return / Risk Estimation | 估计方法是否稳健 |
| Portfolio Construction / Allocation | 配置逻辑是否合理 |
| Optimization | 优化目标是否物有所值 |
| Risk Budgeting | 风险分配是否达成 |
| Rebalancing | 调仓规则的成本收益是否成立 |

### 2.3 回测无法验证的

| 无法验证 | 理由 |
|---|---|
| **未来表现** | 历史不保证未来 |
| **策略在未出现过的市场状态下的表现** | 样本内不存在该状态 |
| **实际可成交性** | 回测只能按规则近似，无法复现真实市场深度 |
| **估计准确性** | **不得以"回测组合表现好"倒推"估计准确"**（上游 ⑤-B） |

## 3. Backtest Type

| 类型 | 说明 | 第一阶段 |
|---|---|---|
| **Historical Backtest** | 在固定区间上一次性重放 | ✅ |
| **Walk-forward Backtest** | 滚动重复 IS→Freeze→OOS | ✅ **必须支持**（`02-business-requirements` §21.5 规则 5） |
| Event-driven Backtest | 按事件而非日历推进 | 已隐含 —— `n` 由 Trigger 决定（`01` §5.2） |

### 3.1 Walk-forward 是第一阶段的必须项 ⚠️

> **上游业务规则明确：单次 IS/OOS 划分可能恰好落在有利区间，滚动验证才能暴露时间稳健性问题。**

```
IS₁ → Freeze₁ → OOS₁
        IS₂ → Freeze₂ → OOS₂
                IS₃ → Freeze₃ → OOS₃
                        ...
```

## 4. In-sample / Out-of-sample（已定案）

> **沿用 `02-business-requirements` §21.5 的六条业务规则，本域不得放宽。**

```
In-Sample (IS)
    ↓  规则设计与参数选择在此完成
Parameter Freeze  ← 参数冻结时点，此后不得再调
    ↓
Out-of-Sample (OOS)
    ↓  仅用于验证，不得据其反向调参
Walk-forward Validation
```

| # | 规则 |
|---|---|
| 1 | **In-Sample 用于**规则设计与参数选择 |
| 2 | **Out-of-Sample 仅用于验证** —— OOS 结果不得用于反向调整参数。一旦据 OOS 调参，该段数据即失去样本外性质 |
| 3 | **Parameter Freeze 时点必须显式记录**，并纳入 Strategy Version |
| 4 | **策略批准必须以 OOS 结果为依据** —— 仅 IS 表现良好不足以批准上线 |
| 5 | **Walk-forward 第一阶段为必须支持** |
| 6 | 若因 OOS 不通过而修改规则，必须**升 Strategy Version 并重新划分 IS/OOS** |

> **推荐默认 · 2026-08-27**：IS : OOS = **70 : 30**，**按时间先后切分，不随机抽样**（同 `P1-14`）。业务方可改。
>
> **「不随机抽样」是硬性要求而非默认** —— 时序数据随机切分会引入前视：用 2024 年的数据训练、用 2020 年的数据验证，等于用未来预测过去。
>
> **70:30 的依据**：OOS 段需满足 `BM-5` 的 1 年下限，30% 在 8 年区间下对应 2.4 年，留有余量。比例可改，但改后须重新核对 OOS 段是否仍满足 1 年。

### 4.1 "OOS 失去样本外性质"是不可逆的 ⚠️

> **这是规则 2 的实质，也是最容易在实践中被侵蚀的一条。**

```
第一次：IS 调参 → OOS 验证 → 不通过
第二次：改了参数 → 用【同一段】OOS 再验证 → 通过

问题：第二次的 "OOS" 已经不是样本外了
    → 参数的修改受到了该段数据的影响
    → 即使修改动机看起来与该段数据无关
```

**因此规则 6 要求重新划分 IS/OOS，而非在同一份数据上反复试错。**

### 4.2 Parameter Freeze 必须是一个可查的时点

> 它不是一个流程约定，而是**纳入 Strategy Version 的字段**（规则 3）。没有它，无法判断某段数据对某组参数而言是否真的样本外。

## 5. Warm-up Period

> **`Backtest Start Date` ≠ 第一次产出组合的日期。**

```
Backtest Start = T₀
Return Estimate 需要 L 期历史
    → 第一个可产出组合的决策日 = T₀ + L
    → [T₀, T₀+L) 是 Warm-up Period
```

### 5.1 Warm-up 长度由最长的输入需求决定

| 输入 | 所需历史 |
|---|---|
| Factor（如 3Y Sharpe） | 由 `04-factor` 各 Factor 的 `Min Obs` 决定 |
| Return Estimate | `07-return-risk` 的 `lookback_window` |
| **Covariance** | `07-return-risk/04` §7.1 的 `T/N` 要求 —— **通常是最长的** |
| Peer Group 历史构成 | `05-fund-evaluation` |

> **`Σ` 的历史需求通常最长** —— 它要求 `T` 显著大于 `N`，而 `N` 是 Universe 规模。

### 5.2 Warm-up 期不计入绩效

```
Warm-up 期：不产出组合、不计交易、不计入净值曲线
绩效计算起点 = warm_up_end_date
```

### 5.3 Warm-up 会缩短有效回测区间

> **这在配置回测区间时必须被计入。**

```
配置 2015–2025（10 年）
Warm-up 需要 3 年
    → 实际有效回测只有 7 年
    → 若再划分 IS/OOS，OOS 可能只有 2–3 年
    → 样本期不足会影响统计判定（§9.4）
```

> **已定案 · 2026-08-27**：最小有效回测区间（Warm-up 之后）= **3 年**。
>
> **依据**：①需覆盖至少一轮完整市场周期 —— 短于 3 年的回测很可能全程处于单一市场环境，其结论无法区分「策略有效」与「恰好适合这段行情」；②与最短评价周期 1Y 的三倍对应，使每只基金在区间内至少有三个完整评价周期。
>
> **本值作用于 Warm-up 之后的有效区间**，配置回测时须倒推：`区间长度 ≥ Warm-up + 3 年`。

## 7. 三方对比（已定案）⚠️

> **沿用 `02-business-requirements` §21.6：只与 Benchmark 比较不够。**

```
Strategy                待验证的策略
    vs
Benchmark               Portfolio Benchmark
    vs
Equal Weight Baseline   同一 Universe 上的等权组合
```

### 7.1 为什么必须有 Equal Weight 基线

> **`Maximum Sharpe` 即使跑赢 Benchmark，也可能跑不赢同一批基金的简单等权组合。**

```
若策略跑赢 Benchmark 但跑不赢等权基线
    → 超额收益来自【选基】（Universe 构成）
    → 而非来自复杂的权重优化
    → 那么优化环节的复杂度就不值得
```

**这是判断"策略复杂度是否物有所值"的唯一方式**（`02-business-requirements` §21.6）。

### 7.2 等权基线必须用同一个 Universe

> **否则比较无效。**

```
❌ 策略用 Score Top-30 的 Universe，等权基线用全市场等权
   → 比较的是两件事的叠加（选基 + 配权），无法分离

✅ 两者用【同一个 Universe(T)】，只有配权规则不同
   → 差异纯粹来自配权
```

### 7.3 等权基线也必须计入交易成本

> 等权组合同样需要定期再平衡，同样产生换手。**用零成本的等权基线对比含成本的策略，会人为抬高策略的相对表现。**

### 7.4 三方对比同样适用于风险维度

| 维度 | 比较内容 |
|---|---|
| 收益 | Total / Annualized Return |
| **风险** | Volatility、Maximum Drawdown |
| 风险调整 | Sharpe、Sortino、Calmar |
| 相对 | Alpha、Beta、TE、IR（相对 Benchmark） |

> **只比收益不比风险会得出错误结论** —— 高收益可能来自高风险敞口。

## 8. Performance Metrics

> **全部指标复用 `04-factor/03-factor-definition` 的定义，本域不新建。**

| 类别 | 指标 | Factor ID |
|---|---|---|
| **收益** | Cumulative Return、Annualized Return | `F-RET-001/002` |
| **风险** | Volatility、Maximum Drawdown、VaR 95%、CVaR 95% | `F-RISK-001/003/004/005` |
| | Downside Volatility | `F-RISK-002` |
| **风险调整** | Sharpe、Sortino、Calmar | `F-RAP-001/002/003` |
| **稳定性** | Win Rate、Rolling Sharpe / Volatility / MDD | `F-STAB-*` |
| **相对** | Alpha、Beta、Tracking Error、Information Ratio、R² | `F-REL-*`、`F-STAB-002` |
| **交易** | Turnover、调仓次数、成本侵蚀比例 | `05-transaction-cost` |

### 8.1 组合层指标不是成分指标的加权 ⚠️

> **沿用 `06-portfolio/04` §2.1。**

```
组合波动率  ≠ Σ w_i × σ_i     → 须由组合净值序列计算
组合最大回撤 ≠ Σ w_i × MDD_i   → 各基金回撤发生在不同时点
组合 VaR    ≠ Σ w_i × VaR_i    → VaR 不满足加权关系
```

**回测的优势在于它有真实的组合净值序列** —— 全部组合层指标直接对该序列计算，不需要近似。

### 8.2 `R_f` 与 Downside Threshold 的一致性

| 指标 | 所需参数 | 要求 |
|---|---|---|
| Sharpe / Alpha / Beta | **`R_f`** | 必须使用 **PIT 的 `R_f`**（`03-data` §3.1.5.2），与 `04-factor` / `07-return-risk` 口径一致 |
| Sortino / Downside Volatility | **下行阈值** | **见 §8.3** |

### 8.3 组合层 Sortino 的下行阈值不应默认为 MAR ⚠️

> **提示词 §34 明确要求不得默认 `MAR = Risk-free Rate`；本域还需再澄清一层。**

```
MAR                 → 单基金评价的阈值（05-fund-evaluation 的 Evaluation Policy）
Downside Threshold  → 风险估计的阈值（07-return-risk/03 §6.3）
组合层 Sortino 的阈值 → 【第三个场景】
```

**本域的处理**：组合层 Sortino 的下行阈值由 **Backtest Configuration 独立声明**，取值可与前两者相同，但**必须是独立字段**。

**理由**：若复用 `MAR`，则改变**单基金的评价标准**会改变**组合回测的绩效指标** —— 两者本无因果关系（沿用 `07-return-risk/03` §6.2 的同一论证）。

> **已定案 · 2026-08-27**：组合层 Sortino 的下行阈值 = **0**，与 `07-return-risk/03` 的 `Downside Threshold` 同值但**独立配置**。
>
> **同值不同源**（同 `RI-7` 的论证）：本项属 `validation_policy`（回测判定），`Downside Threshold` 属 `estimation_policy`（风险估计）。第一版恰好都取 0，但那是两次独立的决策。
>
> **不复用 MAR** —— MAR 是**单基金评价**的阈值（`evaluation_policy`），本项是**组合层回测**的阈值。三者可同值，配置层必须是三个字段。

## 9. 统计显著性判定（落实 BR §22.2）⚠️

> **`02-business-requirements` §22.2 明确：「显著优于」必须由 `08-backtest` 定义具体的统计检验方法与最低标准。**

### 9.1 四层判据（v1.1 定案）

> **沿用 `02-business-requirements` §22.2.1（三重证据 · 2026-08-25）+ §22.2.2（第四层经济显著性 · 2026-08-27）：不依赖单一 p 值，四层全部通过才可称"显著优于"。**

| 层 | 判据 | 说明 |
|---|---|---|
| **① 统计显著性** | **Block Bootstrap 置信区间下界为正** | 重采样构造超额收益分布，区间下界须大于 0 |
| **② 效应量** | **Information Ratio ≥ 阈值** 且 **ΔSharpe ≥ 阈值** | 单位跟踪误差的超额收益 + 标准化后的效应量 |
| **③ 稳健性** | **跑赢概率 ≥ 阈值** | 滚动窗口内跑赢对比基准的比例达标 |
| **④ 经济显著性** | **年化收益改善 ≥ 阈值** 或 **最大回撤改善 ≥ 阈值** | 投资意义上的改善幅度 |

```
① AND ② AND ③ AND ④  →  可称"显著优于"
任一不满足           →  只陈述数值差异
```

> **第四层不替代前三层**：经济显著但统计不显著同样不能称「优于」—— 那可能只是运气。反之亦然：`Sharpe` 高 0.03 且区间下界为正，差异是真实的，但 0.03 在投资上没有意义。

> **为什么 ΔSharpe 并入第②层而非独立成层**：它衡量的是**标准化后**的效应量，与 IR 同类；年化收益/回撤的改善是**未标准化的经济量**，属独立维度。把两者混在一层会让「标准化后显著」被「绝对量微小」掩盖，或反过来。

### 9.2 为什么不用 t 检验（已定案的理由）

> **它在两个方向上同时失真：**

| 方向 | 说明 |
|---|---|
| **样本量不足会漏判** | 5 年月度数据仅 60 个观测。即使策略真实 IR 达到 0.5，t 检验在该样本量下的检出功效也只有五成左右，追求 `p < 0.05` 会拒绝掉大量真实有效的策略 |
| **自相关与肥尾会误判** | 基金收益存在自相关与厚尾，标准 t 检验的独立同分布正态假设不成立，会**高估**显著性 |

> **两个方向的偏差同时存在**，使单一 p 值在本场景下既不敏感也不可靠。

### 9.3 本域对四层判据的执行定义

#### 9.3.1 第②层 · 效应量：Information Ratio 与 ΔSharpe

```
IR = (R_portfolio − R_comparison) / TE
```

| 项 | 说明 |
|---|---|
| **对比对象** | 须**分别**对 Benchmark 与 Equal Weight 基线计算（§7） |
| 公式 | 复用 `04-factor` 的 `F-REL-004` |
| **阈值** | `TBD`（`OPEN-17`） |

> **注意 IR 不依赖 `R_f`**（`04-factor/03-factor-definition`）—— 它是超额收益除以跟踪误差。

**本层的第二个判据 · ΔSharpe**：

```
ΔSharpe = Sharpe_portfolio − Sharpe_comparison
```

| 项 | 说明 |
|---|---|
| **对比对象** | 与 IR 一致，须**分别**对 Benchmark 与 Equal Weight 基线计算 |
| **阈值** | `TBD`（`OPEN-17`，参考量级 0.10） |
| **两个判据的关系** | **AND** —— IR 与 ΔSharpe 须同时达标 |

> **为什么两个都要**：IR 衡量的是「超额相对于跟踪误差」，ΔSharpe 衡量的是「总风险调整后的改善」。一个高换手、高跟踪误差的策略可能 IR 达标而 ΔSharpe 微小 —— 它承担的额外总风险吃掉了超额。只看 IR 会放过这类策略。

> **ΔSharpe 与 IR 使用的 `R_f` 必须一致**（`04-factor/03-factor-definition` §2.1.1 的期限匹配）—— IR 本身不依赖 `R_f`，但 Sharpe 依赖，两个 Sharpe 须用同一 tenor 解析。

#### 9.3.2 第③层 · 稳健性：跑赢概率

```
跑赢概率 = 滚动窗口中 (R_portfolio > R_comparison) 的窗口数 / 总窗口数
```

| 项 | 说明 |
|---|---|
| **滚动窗口长度** | `TBD` —— 长度直接改变结果 |
| **窗口步长** | `TBD` |
| **阈值** | `TBD` |

> **滚动窗口重叠会使观测不独立** —— 这不影响"跑赢概率"作为描述性证据的使用，但**不得据此做独立性假设下的统计检验**。

#### 9.3.3 第①层 · 统计显著性：Block Bootstrap

```
① 将超额收益序列切分为长度 b 的块
② 有放回地重采样块，构造 N 次重采样序列
③ 计算每次重采样的平均超额收益
④ 取该分布的置信区间
⑤ 判定：区间下界 > 0
```

| 参数 | 说明 | 取值 |
|---|---|---|
| **块长 `b`** | 保留自相关结构的关键参数 | `TBD` |
| **重采样次数 `N`** | | `TBD` |
| **置信水平** | | `TBD` |
| **随机种子** | **必须固定并记录** | 见 §9.5 |

> **Block Bootstrap 通过分块重采样保留自相关结构，不依赖分布假设** —— 这正是它替代 t 检验的原因。

**块长的选择是一个实质性判断**：块太短则破坏自相关结构（退化为普通 Bootstrap），块太长则有效重采样样本过少。

#### 9.3.4 第④层 · 经济显著性（v1.1 新增）

> **定案 · 2026-08-27**：`02-business-requirements` §22.2.2、`TBD-resolution.md` Policy ⑨。

```
经济显著 ⟺ (年化收益改善 ≥ 阈值)  OR  (最大回撤改善 ≥ 阈值)
```

| 项 | 说明 |
|---|---|
| 年化收益改善 | `CAGR_portfolio − CAGR_comparison`，参考量级 **1%** |
| 最大回撤改善 | `MDD_comparison − MDD_portfolio`，参考量级 **2%** |
| **两者的关系** | **OR** —— 满足其一即可 |

> **为什么第④层内部是 OR 而第②层内部是 AND**：第②层的两个判据衡量的是**同一件事的两个角度**（超额是否稳健），任一不达标都说明超额不牢靠；第④层的两个判据是**两种不同的投资价值**（赚得更多 / 亏得更少），满足其一就构成实质改善。一个降低回撤但不提高收益的策略，在投资上是有意义的。

> **改善的对比对象与前三层一致** —— 须分别对 Benchmark 与 Equal Weight 基线计算，两者都达标才算通过。跑赢基准但跑不赢等权基线的策略，其复杂度没有换来价值（§7）。

`<OPEN-17: 各层阈值的具体取值，待回测样本校准>`

> 结合 §5.3：Warm-up 会缩短有效区间，因此**配置回测区间时须倒推**：`区间长度 ≥ Warm-up + IS + 最小 OOS 样本期`。

>     → 在季度调仓下只有 3~4 次调仓，样本量不足以判断调仓规则是否有效

### 9.5 Bootstrap 的随机性与可复现的冲突 ⚠️

> **Bootstrap 是本域唯一引入随机性的环节。**

```
不固定种子 → 同一份回测数据两次判定可能结论不同
           → 违反可复现原则（上游 §9 原则六）
```

**要求**：随机种子必须**固定并记录在 Backtest Configuration 中**，与 `06-portfolio/04` §3.3 对蒙特卡洛代理的要求同理。

✅ "该策略在回测期内的年化超额收益为 X%，IR 为 X"

## 10. 必须回答的八个问题

> **沿用 `02-business-requirements` §22.1：仅给出一条净值曲线不满足业务要求。**

| # | 问题 | 判断依据 |
|---|---|---|
| 1 | 策略是否长期有效 | 分年度 / 分阶段收益 |
| 2 | 收益是否稳定 | 滚动收益、滚动 Sharpe 的波动 |
| 3 | 最大回撤是否可接受 | MaxDD、Drawdown Duration |
| 4 | 是否存在明显失效阶段 | 分阶段超额收益 |
| 5 | **是否过度依赖某些基金** | 收益归因至个基的集中度 |
| 6 | **是否过度依赖某些市场环境** | 分市场环境的表现 |
| 7 | 换手率是否过高 | Turnover、成本侵蚀比例 |
| 8 | 是否优于 Benchmark **与 Equal Weight 基线** | 三方对比（§7） |

### 10.1 第 5、6 项是过度依赖的识别

> **沿用 `02-business-requirements` §22.3：**

| 类型 | 含义 |
|---|---|
| **过度依赖某些基金** | 收益集中于一两只基金 = **在押注个基而非依靠规则** |
| **过度依赖某些市场环境** | 超额收益全部产生于某一段行情 |

> **两者都会使回测结论失效** —— 它们说明"策略有效"实际上是"运气好"。

> **推荐默认 · 2026-08-27**：单一年度贡献 **> 50%** 总超额判为**收益集中**；单一市场环境贡献 **> 70%** 判为**环境依赖**。业务方可改。
>
> **两个阈值的含义不同**：
>
> | 判定 | 含义 | 后果 |
> |---|---|---|
> | 收益集中 | 超额高度依赖某一年 | 该策略可能只是抓住了一次机会，不具备可重复性 |
> | 环境依赖 | 超额高度依赖某类市场（如仅在牛市有效） | 策略在其它环境下可能失效甚至反向 |
>
> **两者都不是否决项，而是必须在报告中呈现的特征** —— 一个只在牛市有效的策略仍可能是有用的，只要使用者知道这一点。

## 11. Overfitting

### 11.1 回测不是参数搜索工具

> **上游 §4.2 ⑧ 边界条款：反复调参直到回测好看属于过拟合，参数选择须有独立的样本外验证。**

### 11.2 第一阶段默认不做参数搜索

```
Parameter Optimization = OFF（第一阶段）
```

**若未来支持，必须独立设计**：Training / Validation / Test 三段划分，且 Test 段不参与任何选择。

### 11.3 "不搜索参数"不等于"没有过拟合风险" ⚠️

> **即使不做自动搜索，人工的反复试验同样是搜索。**

```
研究员试了 5 种 Universe 规则、3 种权重方法、2 种调仓频率
    → 30 种组合，最终选了回测最好的一种
    → 这与自动网格搜索在统计上没有区别
```

**要求**（沿用 `07-return-risk/06` §13.2 的同一原则）：

| # | 要求 |
|---|---|
| 1 | **尝试过的配置数量必须记录** —— 它是判断结论可信度的必要信息 |
| 2 | 被放弃的配置及其回测结果应留存 |
| 3 | 最终配置必须在**未参与选择的时段**上验证 |

## 12. Multiple Testing

> **比较大量策略、参数、基金或组合时，会产生 Data Mining Bias。**

```
测试 100 个无效策略
    → 在 5% 显著性水平下，预期约 5 个会"通过"检验
    → 这 5 个不是有效策略，是随机噪声
```

### 12.1 三重证据部分缓解但不消除该问题

> §9 的三重证据比单一 p 值稳健，但**它仍是对单个策略的判定** —— 若对 100 个策略各做一次三重证据判定，同样会有假阳性。

**要求**：报告必须披露**本次判定是从多少个候选中选出的**。

> **已定案 · 2026-08-27**：第一阶段**不做多重检验校正**，但**必须记录并呈现尝试过的配置数量**。
>
> **依据 —— 校正方法的选择本身是又一个决策**：
>
> | 方法 | 问题 |
> |---|---|
> | Bonferroni | 过于保守，在尝试次数多时几乎否决一切 |
> | FDR（Benjamini-Hochberg） | 需要指定可接受的错误发现率，又是一个待定参数 |
> | Deflated Sharpe Ratio | 需要估计尝试次数的有效自由度，而这在人工调参场景下难以确定 |
>
> **让多重检验背景可见，比用一个未经论证的校正掩盖它更诚实**：报告呈现「本次结论基于第 N 次配置尝试」，使用者据此自行调整对结论的信心。
>
> ⚠️ **「记录尝试次数」必须是系统强制的，不能依赖自觉** —— 否则实际尝试 50 次只报告 1 次，本条形同虚设。实现方式：同一 `strategy_id` 下的回测运行计数自动累加并写入报告。

## 14. Backtest Limitations

> **必须在报告中显式披露**（`06-backtest-report` §14）。

| 类别 | 说明 |
|---|---|
| **历史依赖** | 回测只能覆盖历史出现过的市场状态 |
| **模型风险** | 估计方法、优化目标的选择本身是假设 |
| **参数风险** | 参数在历史上有效不保证未来有效 |
| **数据风险** | 数据修订、缺失、质量问题会影响结果 |
| **执行假设** | 成交价格、时滞、可成交量的简化 |
| **成本假设** | 成本模型的简化与参数不确定性 |
| **样本期限制** | OOS 段长度可能不足以支撑强结论 |

### 14.1 最根本的一条

> **回测不保证未来表现。** 历史表现不能保证未来表现 —— 这不是免责声明的套话，而是回测方法论的固有限制：回测只能回答"若当时如此做会怎样"，不能回答"今后如此做会怎样"。

## 18. Edge Cases

| 情形 | 处理 |
|---|---|
| OOS 段长度低于最小样本期 | **不得给出"显著优于"结论**；只陈述数值 |
| Benchmark 缺失 | 相对指标（Alpha/Beta/TE/IR）不可算；**证据一不可用 → 三重证据不成立** |
| 等权基线不可构造（Universe 为空） | 该期基线缺失，须在报告中标注 |
| 回测期内策略从未调仓 | Turnover = 0；成本侵蚀为 0，但须核查是否为触发条件配置错误 |
| 全部超额收益来自单一时段 | §10 第 6 项判定为**环境依赖**，须在报告中突出 |
| 全部超额收益来自单只基金 | §10 第 5 项判定为**个基依赖** |
| Bootstrap 区间下界恰为 0 | 判定为**不通过** —— 要求严格大于 0 |
| IS 与 OOS 表现差异悬殊 | 过拟合信号，须在报告中标注 |

### 19.1 判定过程必须完整留痕

| 必须记录 | 理由 |

## 20. Summary

回测验证的是**规则**，不是结果；它回答"若当时如此做会怎样"，**不回答"今后如此做会怎样"**。

三条已定案、本域不得放宽的业务规则：

- **OOS 仅用于验证，且"失去样本外性质"是不可逆的** —— 据 OOS 调参后，即使改回来，那段数据也不再是样本外；因此规则要求重新划分而非反复试错
- **必须三方对比，且等权基线用同一 Universe、同样计成本** —— 跑赢 Benchmark 但跑不赢等权，说明超额来自选基而非配权，优化环节的复杂度不值得
- **Walk-forward 是必须项** —— 单次 IS/OOS 划分可能恰好落在有利区间

本域落实的统计判定（BR §22.2 点名）：

- **三重证据：IR 达阈值 + 跑赢概率达阈值 + Block Bootstrap 区间下界为正**，三条全通过才可称"显著优于"
- **不用 t 检验的理由是它在两个方向上同时失真** —— 小样本漏判（60 个观测下检出功效仅约五成）、自相关与肥尾误判（高估显著性）
- **阈值确定前，报告不得使用"显著优于"表述**，只能陈述数值差异

三处容易被低估的问题：

- **Warm-up 会缩短有效回测区间** —— `Σ` 的历史需求通常最长；配置区间时须倒推 `Warm-up + IS + 最小 OOS`
- **"不做参数搜索"不等于没有过拟合风险** —— 人工试了 30 种组合再选最好的，与自动网格搜索在统计上没有区别
- **组合层 Sortino 的下行阈值是第三个场景** —— 既不是 `MAR`（单基金评价）也不是 `07-return-risk` 的 `Downside Threshold`（风险估计），须由 Backtest Configuration 独立声明

一处随机性：**Bootstrap 是本域唯一引入随机性的环节，种子必须固定并记录**。
