### 1.2 为什么它与前视偏差同等重要

| | Look-ahead Bias | Survivorship Bias |

## 2. Definition

> **只使用当前仍然存在的基金构造历史样本。**

```
2022-01-01 的 Peer Group 与 Universe
  ✓ 应为：当时实际存在且符合条件的全部基金
  ✗ 不得为：2026 年仍存续的基金中符合条件的那些
```

（`02-business-requirements` §26.2）

## 3. 为什么会高估收益

> **清盘的往往是表现差的基金，剔除它们相当于事先知道哪些会失败并提前避开。**

```
2022 年存在 1500 只基金
到 2026 年仍存续 1000 只
    → 消失的 500 只中，多数因业绩差、规模萎缩而清盘
    → 用今天的 1000 只回溯 2022 年
    → 等于在 2022 年就"知道"这 500 只会出事并避开
```

### 3.1 影响不止于收益 ⚠️

| 受影响的量 | 方向 | 机制 |
|---|---|---|
| **平均收益** | **高估** | 差基金被剔除 |
| **波动率** | **低估** | 高波动基金更易清盘 |
| **最大回撤** | **低估** | 大幅回撤常导致清盘 |
| **相关性** | **低估** | 见 §3.2 |
| **Peer Group 分位** | **失真** | 见 §3.3 |

### 3.2 对相关性的影响最危险

> **沿用 `07-return-risk/01` §9.2。**

```
市场危机期间同时下跌的基金，部分在其后清盘
    → 用当前存续基金估计相关性，恰好漏掉了这些"共同下跌"的样本
    → 相关性被系统性【低估】
    → 优化器认为分散化效果比实际更好
```

**这比收益高估更危险** —— 它使组合在**最需要分散化的时候**失效。

### 3.3 对 Peer Group 分位的影响会传导至全组

```
Peer Group 缺少后来清盘的低分基金
    → 幸存者的分位被系统性【压低】？不 —— 恰恰相反
    → 缺少的是【低分】成员 → 剩余基金的分位被【抬高】
    → 全组的 Score 与 Tier 都偏高
```

> **注意方向**：剔除差基金后，剩下的基金在"更小且更优"的组里排名，其分位反而**下降**（同样的绝对水平在强组中排名更后）。但因为整组都变强，**Tier 阈值对应的绝对水平被抬高** —— 两种效应叠加，结果是分位分布整体失真，**方向依组内分布而定**。

**因此不能简单说"分位被高估或低估"，只能说"失真且不可预测"** —— 这正是必须用历史快照而非重建的理由。

## 4. Historical Universe

### 4.1 核心要求

```
每个决策日 T：使用 Universe(T)，而非 Universe(current)
```

### 4.2 快照优先（沿用 `01-backtest-engine` §8.2）

| 场景 | 处理 |
|---|---|
| **快照存在** | **直接读取** —— 天然避免幸存者偏差 |
| 快照不存在，满足可重建条件（`01` §8.3） | 重建并标记 |
| 不满足 | **中止** |

### 4.3 为什么快照能"天然避免"幸存者偏差

> **快照记录的是当时的成员列表** —— 它不需要判断"谁还活着"，因为那份列表就是当时的事实。

```
重建则必须回答：2022-01-01 有哪些基金存续且合格？
    → 依赖生命周期数据的完整性
    → 若某只基金的清盘记录缺失，重建时它会被误判为"不存在"或"仍存续"
```

```

**因此本域的检测必须能识别"数据本身就缺"与"回测用错了样本"两种情形**（§12.2）。

## 6. Eligibility：入池的时点条件

```
Fund ∈ Universe(T)  当且仅当：
    launch_date ≤ T
    且 T 时点未终止
    且 满足当时的 Eligibility Rules
```

### 6.1 "成立日 ≤ T" 还不够 ⚠️

> **新成立的基金还需满足最小历史长度要求。**

```
Fund A 成立于 2022-01-01
决策日 T = 2022-02-01
    → 成立日 ≤ T ✓
    → 但 3Y Sharpe 不可算 → Factor UNAVAILABLE
    → 若 Universe 规则要求该指标，它仍不入池
```

**这不是幸存者偏差，而是正常的准入判定**（`05-fund-evaluation/05` §6）。两者不可混淆 —— 前者是"不该排除却排除了"，后者是"本就不该入池"。

## 7. 清盘基金的处理

### 7.1 不得简单删除

```
❌ 基金清盘 → 从历史数据中删除 → 它从未存在过
   → 这正是幸存者偏差的成因
```

### 7.2 三个层面的处理

| 层面 | 处理 |
|---|---|
| **历史数据** | **完整保留**，含清盘前的全部净值序列 |
| **Universe 成员资格** | 清盘日之前正常在池，之后自动出池 |
| **持仓处理** | 见 §7.3 |

### 7.3 组合持有的基金在期内清盘

> **上游 `02-business-requirements` §26.2 要求"组合成分清盘时按事先定义的规则处理退出"。**

**必须事先定义的三项**：

| # | 项 | 说明 |
|---|---|---|
| 1 | **退出时点** | 清盘公告日 / 最后交易日 / 清算完成日 |
| 2 | **退出价格** | 最后净值 / 清算净值 —— 两者可能有显著差异 |
| 3 | **资金去向** | 转为现金 / 按比例分配给其余持仓 / 下期再平衡时处理 |

```
Liquidation Handling = TBD
```

> **已定案 · 2026-08-27**：持仓基金清盘时，以**清盘公告日的净值**退出，资金**转入现金**，**下一调仓日**重新分配。
>
> **三个环节各自的理由**：
>
> | 环节 | 决策 | 为什么 |
> |---|---|---|
> | 退出价格 | **清盘公告日净值** | 用最后净值即前视 —— 决策时点上「最后净值」还未产生。公告日是市场首次得知该基金将清盘的时点 |
> | 资金去向 | **转入现金** | 立即再投资等于假设了一次不存在的即时交易；且清盘公告与实际清算之间有时滞 |
> | 再分配时点 | **下一调仓日** | 与正常调仓节奏一致，不为清盘事件破例触发额外调仓 |
>
> **这使清盘对组合的影响完整体现**：先是持有一只将要清盘的基金（可能已开始下跌），然后是一段持币期（无收益），最后才重新配置。**任一环节的简化都会让清盘看起来比实际更无害。**

### 7.4 清盘往往伴随一段异常净值 ⚠️

```
基金进入清算期
    → 停止申赎、变现资产
    → 净值可能出现异常波动或长期不更新
    → 若按最后净值退出，可能已包含清算损耗
    → 若按公告日退出，则忽略了清算期的实际损失
```

**两种处理的结果不同，且都不完全准确** —— 必须显式选择并在报告中声明。

### 7.5 不得因清盘而回溯修改历史表现

> 清盘前该基金的历史收益是真实发生的，**不因其后来清盘而失效**。回测中它在存续期的贡献必须如实计入。

## 8. 合并基金

> **`Fund A → Fund B` 的合并是最复杂的一类生命周期事件。**

### 8.1 四项必须明确

| # | 项 | 问题 |
|---|---|---|
| 1 | **历史连续性** | 合并后 B 的历史是否接续 A？ |
| 2 | **持仓处理** | 持有 A 的份额如何转为 B 的份额？ |
| 3 | **净值处理** | 换股比例如何反映在净值序列上？ |
| 4 | **收益处理** | 合并当日的收益如何计算？ |

```
Merger Handling = TBD
```

### 8.2 历史连续性的两种口径，结果不同 ⚠️

| 口径 | 做法 | 后果 |
|---|---|---|
| **接续** | B 的历史 = A 的历史 + B 的历史 | 若 A 表现差、B 表现好，接续会**稀释** B 的历史优势；反之则**美化** |
| **不接续** | A 在合并日终止，B 视为独立基金 | A 的历史被完整保留，B 从合并日起算 |

> **接续口径存在一个隐患**：合并往往是"差基金并入好基金"，若统一按接续处理，会让存续基金的历史被人为拉低 —— 这是与幸存者偏差**方向相反**的一种失真，但同样是失真。

### 8.3 本域倾向不接续，但须业务确认

**理由**：不接续更符合"当时的事实" —— 在合并日之前，A 与 B 是两只独立的基金，当时的投资者面对的就是两个独立选择。

> **已定案 · 2026-08-27**：合并基金按「**存续方历史延续，被合并方历史终止**（视同清盘）」处理。
>
> **依据 —— 把被合并方历史接续到存续方会制造虚假的长历史**：
>
> ```
> A 基金（3 年历史，表现差）并入 B 基金（5 年历史，表现好）
>
> 若接续：B 的历史变成「A 的 3 年 + B 的 5 年」？还是「B 的 5 年」？
>     → 前者：混合了两个不同的投资组合与管理团队
>     → 后者：正确，但 A 的持有人经历的那 3 年就消失了
> ```
>
> **正确处理是把 A 视同清盘**：A 的历史保留在数据中（`FO-2` 永久保留）、其持有人在合并日「退出」、资金按存续方处理。**B 的历史不受影响。**
>
> **净值的连续性**：合并通常伴随份额折算，被合并方持有人按折算比例获得存续方份额。回测中体现为「按 A 的最后净值退出、按 B 的当日净值买入」，其经济含义与折算等价。

## 9. Fund Classification 的 PIT

> **历史分类必须使用当时的版本。**

```
❌ 用今天的分类覆盖历史
   → Peer Group 归组错误
   → Benchmark Mapping 错误
   → Asset Class 归属错误
```

（详见 `03-look-ahead-bias` §12.3 —— 这既是版本前视也影响样本构成）

### 9.1 转型使基金"换了一只"但 ID 不变 ⚠️

```
Fund A 从偏债混合型转为偏股混合型
    → ID 不变、净值序列连续
    → 但转型前后【不是同一个投资标的】
```

**回测中的后果**：

| 后果 | 说明 |
|---|---|
| Peer Group 跨期不可比 | 转型前在债券组，转型后在股票组 |
| Factor 跨期不可比 | 收益序列混合了两种策略 |
| Benchmark 跨期不可比 | 基准变更 |

**处理**：窗口跨越转型点的估计与评价须标 `WARNING`（`07-return-risk/01` §18.2、`04-factor` 相关约束）。

## 11. Tradability Bias（第三类偏差）⚠️

> **沿用 `02-business-requirements` §26.3。**

### 11.1 定义

> **即使数据 PIT 正确、样本无幸存者偏差，若回测在基金暂停申购期照常建仓，结果同样失真** —— 那笔交易在现实中根本无法成交。

### 11.2 为什么它是独立的第三类

```
Look-ahead   ：用了当时不知道的【信息】
Survivorship ：用了当时不存在的【样本】
Tradability  ：做了当时做不到的【交易】
```

三者互相独立 —— 满足前两者不蕴含满足第三者。

### 11.3 检查要求

> **回测每次建仓/加仓必须校验 `Investment Eligibility`**（`02-business-requirements` §18.2、§21.8）。

| 状态 | 可建仓 | 可加仓 | 可持有 | 可减仓 |
|---|:---:|:---:|:---:|:---:|
| `FULLY_ELIGIBLE` | ✓ | ✓ | ✓ | ✓ |
| **`HOLD_ONLY`**（暂停申购） | **✗** | **✗** | ✓ | ✓ |
| `LIMITED` | 受限 | 受限 | ✓ | ✓ |
| `EXIT_ONLY` | ✗ | ✗ | ✓ | ✓ |
| **`NOT_TRADABLE`** | ✗ | ✗ | — | **✗** |

### 11.4 `HOLD_ONLY` 的基金不移出 Universe

> **沿用 `05-fund-evaluation/05` §9.2、`06-portfolio/06` §10：** 直接过滤掉会导致已持仓被强制清仓。正确做法是**入池并标注不可建仓**。

### 11.5 无法达成目标权重时必须显式报告差额

> **不得静默用其他基金补足**（`02-business-requirements` §28.4）。

```
❌ Fund A 因 HOLD_ONLY 只买到 8%（目标 15%）→ 悄悄把 7% 给 Fund B
   → 回测执行的组合与记录的 Target 不符
   → 归因失效
```

### 11.6 Tradability 检查在回测中容易被跳过

> **它需要 `Investment Eligibility` 的历史数据**，而这类数据（暂停申购公告）往往不如净值完整。

**处理**：该数据缺失时，**不得默认为 `FULLY_ELIGIBLE`** —— 应标 `WARNING` 并在报告中声明该期的可交易性未经校验。

> **已定案 · 2026-08-27**：`Investment Eligibility` 历史缺失时该期标 **`NOT_VERIFIED`**，**不假定可投资**。
>
> **依据 —— 假定可投资即 Tradability Bias**：
>
> ```
> 缺失时假定可投资
>     → 回测可能在基金暂停申购的期间建仓
>     → 该笔交易在现实中【不可能发生】
>     → 而回测把它的收益算进了结果
> ```
>
> **`NOT_VERIFIED` 不等于 `INVALID`**（§12.1，不变）：它表示「无法验证这一期是否可交易」，是一个独立状态。回测仍可运行，但**其 Tradability 检查结论为「未验证」**，不得声称无 Tradability Bias。
>
> **`NOT_VERIFIED` 期占比须在报告中呈现** —— 与重建期占比、`INFERRED` 占比并列，共同构成「这份回测有多可信」的完整图景。
>
> **本项与 `03-data` 的 Eligibility 历史完整性直接相关**：若该历史长期缺失，正确的动作是补数据，而不是调整回测规则。

## 12. Detection

### 12.1 基础检测

```
对每个决策日 T：
    assert Backtest_Universe(T) == Historical_Universe(T)
否则 → FAIL
```

### 12.2 数据缺失与用错样本必须区分 ⚠️

> **两者的检测结论相同（样本不符），但成因与处置完全不同。**

| 情形 | 成因 | 处置 |
|---|---|---|
| **回测用了 `Universe(current)`** | 实现错误 | **修复代码**，回测 `INVALID` |
| **历史 Universe 快照缺失且数据不全** | 数据层缺口 | **中止回测**（`01` §8.3），并上报数据缺口 |
| **已清盘基金的历史数据本就没有** | Provider 能力限制 | **平台层无法修正**（§5.1），须在报告中声明该局限 |

> **第三种情形不是 bug** —— 它是能力边界，必须如实披露而非掩盖。

### 12.3 逐期检测项

| 检测 | 判定 |
|---|---|
| Universe 成员数与快照一致 | 不一致 → `FAIL` |
| 每只成员 `launch_date ≤ T` | 违反 → `FAIL` |
| **每只成员在 T 时未终止** | 违反 → `FAIL` |
| **当时存续但未入池的基金，有明确排除原因** | 无原因 → `FAIL`（`05-fund-evaluation/05` §14.3） |
| Classification 使用当时版本 | 违反 → `FAIL`（并计入 §9 的版本前视） |
| **建仓/加仓的标的 `Investment Eligibility` 允许** | 违反 → `FAIL`（Tradability） |

### 12.4 "当时存续但未入池"必须有原因

> **这是幸存者偏差最有效的检测点。**

```
若某基金在 T 时存续但不在 Universe(T) 中
    → 必须能说明是哪条 Eligibility Rule 排除了它
    → 说不出原因 = 它被"悄悄"排除了
    → 很可能就是因为它今天已不存在
```

## 13. Audit

> **每个决策日必须记录：**

| 字段 | 说明 |
|---|---|
| **`universe_date`** | Universe 的时点 |
| **`universe_source`** | `SNAPSHOT` / `REBUILT`（`01` §8.4） |

| **`ineligible_funds`** | **当时存续但未入池的基金** |
| **`exclusion_reasons`** | 逐只的排除原因 |
| **`lifecycle_status`** | 逐只的生命周期状态 |
| **`investment_eligibility`** | 逐只的可投资性状态 |
| **生命周期事件** | 该期发生的成立 / 清盘 / 合并 / 转型 |

### 13.1 `ineligible_funds` 是必备字段，不是可选

> 只记录入池的基金，**无法验证是否有基金被错误排除** —— 而错误排除正是幸存者偏差的表现形式。

## 14. 两个例子

### 14.1 例一：使用当前 Universe 回溯历史

```
当前市场存在 1000 只符合条件的基金
2020-01-01 实际存在 1500 只

❌ 回测用今天的 1000 只跑 2020–2026
   → 消失的 500 只中多数因业绩差清盘
   → 回测组合从未持有过它们
   → 年化收益被高估、波动率与回撤被低估
   → 相关性被低估 → 优化器高估分散化效果

✅ 用 Universe(2020-01-01) 的 1500 只
   → 组合可能选中其中后来清盘的基金
   → 那次清盘造成的损失【应当】计入回测
```

**影响的量级取决于清盘率** —— 清盘率越高的市场，偏差越大。

### 14.2 例二：Peer Group 缺少已清盘基金

```
2020-01-01 的股票型 Peer Group
  实际有 800 只
  用今天的成员重建 → 只剩 550 只

后果：
  ① 分位标准化的样本集变小且偏优
  ② 全部基金的 Normalized Score 失真
  ③ Fund Tier 的分位阈值（5/20/50/80）对应的绝对水平被抬高
  ④ Universe 的 Score Top-N 筛选结果改变
  ⑤ 最终组合成分与当时完全不同
```

> **注意这是一条完整的传导链** —— Peer Group 的一处偏差沿 Score → Tier → Universe → Portfolio 逐级放大。

## 16. Edge Cases

| 情形 | 处理 |
|---|---|
| 基金成立日恰好等于 `T` | 入池条件是 `≤`，故**通过**；但历史长度必然不足（§6.1） |

```

```

> **这不是 bug，是数据完整性提升的正常结果** —— 但必须能被解释，因此 Universe 快照引用与数据版本必须一同留存。

## 19. Summary

幸存者偏差与前视偏差同样不可见，但成因不同：前者是**用了当时不存在的样本构成**，防范手段是**历史 Universe 快照**。

三处影响范围的澄清：

- **影响不止于收益** —— 波动率与最大回撤同样被低估（高波动、大回撤的基金更易清盘）
- **对相关性的影响最危险** —— 危机期同跌的基金部分已清盘，剔除它们使相关性被系统性低估，组合在**最需要分散化时**失效
- **对 Peer Group 分位的影响是"失真且不可预测"** —— 不能简单说高估或低估，两种效应叠加，方向依组内分布而定；这正是必须用快照而非重建的理由

三类生命周期事件的处理要点：

- **清盘往往伴随异常净值** —— 按最后净值退出可能已含清算损耗，按公告日退出则忽略清算期损失；两种处理都不完全准确，必须显式选择并声明
- **合并的"接续"口径存在反向失真** —— 合并常是差基金并入好基金，统一接续会人为拉低存续基金的历史，这是与幸存者偏差方向相反但同样是失真
- **转型使基金"换了一只"但 ID 不变** —— 净值序列连续但前后不是同一个投资标的

本文档并入的第三类偏差：**Tradability** —— 三者互相独立（用了不知道的信息 / 不存在的样本 / 做不到的交易），满足前两者不蕴含满足第三者。其数据（暂停申购公告）往往不完整，**缺失时不得默认 `FULLY_ELIGIBLE`**。

两个检测要点：

- **"当时存续但未入池"必须有明确原因** —— 这是幸存者偏差最有效的检测点；说不出原因就是被"悄悄"排除了
- **数据缺失与用错样本必须区分** —— 前者是能力边界须如实披露，后者是 bug 须修复；混为一谈会让真正的实现错误被当作数据问题放过

## 20. Decisions

| # | 决策 | 理由 |
|---|---|---|
| D-1 | **快照优先**，重建为例外 | 快照是当时的事实，不需判断"谁还活着" |
| D-2 | 清盘基金历史数据**完整保留**，不删除 | 删除即制造偏差 |
| D-3 | **不因清盘而回溯修改历史表现** | 存续期的收益是真实发生的 |
| D-4 | 清盘退出的时点、价格、资金去向须**事先定义** | 两种处理结果不同且都不完全准确 |
| D-5 | **合并倾向不接续**（待业务确认） | 更符合"当时的事实" |
| D-6 | Classification 必须用当时版本 | 影响 Peer Group / Benchmark / Asset Class 三条链路 |
| D-7 | 跨转型点的估计与评价标 `WARNING` | 前后不是同一投资标的 |
| D-8 | **Tradability 并入本文档** | 与幸存者偏差同属样本可用性问题 |
| D-9 | `HOLD_ONLY` **不移出 Universe**，标注不可建仓 | 移出会导致已持仓被强制清仓 |
| D-10 | **`Investment Eligibility` 缺失时不得默认 `FULLY_ELIGIBLE`** | 把"不知道"当作"可以交易" |
| D-11 | **`ineligible_funds` 与排除原因是必备字段** | 否则无法验证是否有基金被错误排除 |
| D-12 | **区分数据缺失与用错样本** | 前者是能力边界，后者是 bug |
| D-13 | 区分"不该排除却排除了"与"本就不该入池" | 后者是正常准入判定，不是偏差 |
