## 2. Historical Return vs Expected Return ⚠️

> **本文档最核心的一条边界。**

| | **Historical Return** | **Expected Return** |
|---|---|---|
| 含义 | 观测到的历史表现 | 面向未来的估计 |
| 归属 | `04-factor` | **本域** |
| 版本 | `Metric Version` | **`Return Estimate Version`** |
| 是否含假设 | 否 —— 它是事实 | **是** —— 含"历史可外推"的假设 |
| 必须声明的口径 | Window | **Window + Horizon + Basis** |

### 2.1 不能默认 `Expected Return = Historical Return`

> **除非 Policy 明确采用历史平均作为估计方法。**

即使采用，两者仍是不同字段（`01` §5.1）：

```
同一个"历史 36 个月均值"
  作为 Factor：  "过去 36 个月平均涨了 X%"        —— 事实陈述
  作为 Estimate："假设未来一个持有期会涨 X%"      —— 含外推假设
```

**外推假设是可以被质疑、被验证、被换掉的**，因此需要独立的版本治理与校验流程（`06`）。

### 2.2 `μ` 必须与 `Fund Score` 逻辑独立

> **上游 §5.2 的强制规则：**

```
❌ 由 Score 换算、映射或缩放得到 μ
✅ μ 由 Fund Data 的历史收益序列独立计算
```

三条理由（上游 §5.2）：**量纲错误**（Score 无量纲，`λ` 失去意义）、**不可加总**（Score 相加没有金融含义）、**目标错配**（排序正确不代表数值可用）。

> **`Score Weight` 策略不违反本条** —— 它是在 Construction 层显式选择的加权规则，不是把 Score 当收益率喂进优化器（`06-portfolio/01` §8.2）。

## 3. Return Definition

### 3.1 收益率定义沿用 `03-data`

> **本域不新建收益率定义。** 沿用 `03-data/05-data-normalization` §6 Return Normalization。

| 定义 | 公式 |
|---|---|
| **Simple Return** | `R_t = P_t / P_{t-1} − 1` |
| **Log Return** | `r_t = ln(P_t / P_{t-1})` |

其中 `P` 为**复权净值**（Adjusted NAV），复权口径见 `03-data/05-data-normalization` §5.3。

### 3.2 Simple 与 Log 的选择影响可加总性 ⚠️

> **这不是一个纯技术选择。**

| | Simple Return | Log Return |
|---|---|---|
| **跨时间可加** | ❌ | ✅ `r_{1→3} = r_1 + r_2 + r_3` |
| **跨资产可加**（组合层） | ✅ `R_p = Σ w_i R_i` | ❌ |

```
均值-方差框架要求 μ 在【组合维度】可加总（μ'w 有意义）
    → 因此 μ 应基于 Simple Return
    → 但 Log Return 在时间维度上更便于年化与复利处理
```

**要求**：所用定义必须在 `Return Estimation Policy` 中显式声明，且**与 `Σ` 的定义一致**（`04` §3）。混用会使 `w'Σw` 与 `μ'w` 处于不同的收益定义下。

> **已定案 · 2026-08-27**：采用 **Simple Return**。见 `TBD-resolution-2.md` Policy F。

**依据来自本节自身的论证** —— §3.2 已写明「均值-方差框架要求 μ 在**组合维度**可加总（`μ'w` 有意义）→ 因此 μ 应基于 Simple Return」。本次只是把该论证正式落案。

**两个连带约束**：

| # | 约束 |
|---|---|
| 1 | **`Σ` 必须用同一定义** —— 混用会使 `w'Σw` 与 `μ'w` 处于不同收益定义下，目标函数的两项不在同一量纲上（`04-correlation-covariance` §3 一并适用） |
| 2 | 与 `04-factor/04-factor-calculation` §5.1 的因子层口径**一致** —— 若本域选 Log，同一只基金的「因子层年化收益」与「估计层 μ」会是两个不同的数 |

> **Log Return 的跨时间可加性在本系统中价值有限**：本域的估计对象是**单期**期望收益（Horizon = 调仓周期），不做多期复合；而组合层加总是每次优化都要做的。两个性质的使用频率相差悬殊。

### 3.3 Return Frequency

> 沿用 `03-data` 与 `04-factor` 的既有定义，**不新建标准**。

| 频率 | 说明 |
|---|---|
| **Daily** | 主要来源，与 NAV 频率一致 |
| Weekly / Monthly | 由日频聚合而来 |

> 频率选择与观测数、年化因子直接相关，见 `05` §9。

## 5. Return Estimation Methods

### 5.1 上游允许的五种方法（已定案）

| # | 方法 | 说明 | 使用时必须注意 |
|---|---|---|---|
| 1 | **Historical Mean** | 历史收益均值 | 需声明窗口与年化口径 |
| 2 | **Historical CAGR** | 历史几何年化收益 | **CAGR 是已实现收益率，不天然等于下一持有期的估计** |
| 3 | **Rolling Mean** | 滚动窗口收益均值 | 需声明窗口与更新频率 |
| 4 | **Benchmark-relative Return** | 相对基准的历史超额收益 | **产出的是 Expected Excess Return** |
| 5 | **Shrinkage Estimate** | 向基准或总体均值收缩 | 需声明收缩目标与强度 |

```

```

> **推荐默认 · 2026-08-27**：生产采用**历史均值 + 收缩**（Shrinkage）。业务方可改，改动只需升 `estimation_policy` 版本。
>
> **依据**：本系统第一阶段不引入预测模型（上游 §6.2.1 排除 ML）。在无预测的前提下，历史均值是**无偏**的期望估计；其唯一缺陷是方差大，而收缩正是针对该缺陷的标准修正。两者组合是「不预测」约束下的自然选择。

### 5.2 Historical Mean

```
算术平均：  E[R] = (1/N) Σ R_t
```

**使用条件**：

| 条件 | 说明 |
|---|---|
| 观测数 ≥ 最小样本量 | `06` §9 |
| 年化口径统一为 252 交易日 | `05` §9 |
| 窗口内无重大结构性断点 | `01` §18.2 |

> **算术平均是无偏的期望估计**，但方差很大 —— 这正是 Shrinkage（§5.6）存在的理由。

### 5.3 Historical CAGR 与算术平均的区别 ⚠️

> **两者在数学上不同，且差异随波动率增大而增大。**

```
CAGR（几何平均） = (Π(1 + R_t))^(1/T) − 1
算术平均          = (1/N) Σ R_t

近似关系：  CAGR ≈ 算术平均 − σ²/2
```

| | CAGR | 算术平均 |
|---|---|---|
| 回答 | 过去**实际实现**的年化收益 | 单期收益的**期望** |
| 用于 `μ` | **需显式声明外推假设** | 直接作为单期期望 |
| 波动率影响 | 波动越大，越低于算术平均 | 不受影响 |

> **上游 ⑤-A 明确**：CAGR 是已实现（realized）收益率，**不天然等于下一持有期的收益估计**。作为 `Return Estimate` 使用时，必须显式声明 Estimation Horizon 及"以历史 CAGR 外推该持有期"这一假设。

**均值-方差框架要求的是单期期望**，因此若采用 CAGR，需明确它与目标函数中 `μ` 的对应关系。

#### 5.3.1 已定案 · 2026-08-27：CAGR 不进优化，仅用于展示

> **定案**：`μ` 采用**算术平均**；**CAGR 仅用于展示层**，不作为优化输入。见 `TBD-resolution-2.md` Policy F。

**依据 —— CAGR 已经内含一次风险扣减**：

```
CAGR ≈ 算术平均 − σ²/2

把 CAGR 当作 μ 输入均值-方差优化
    → 目标函数 max( μ'w − λ·w'Σw ) 中
    → 风险被惩罚【两次】：一次藏在 μ 里，一次在 w'Σw 里
    → 结果系统性偏向低波动资产
```

> **这个偏差不是「更保守」那么简单** —— 双重惩罚的程度随每只基金各自的 `σ²` 变化，因此它不等价于调大风险厌恶系数 `λ`。**它是一个无法用任何 `λ` 复现的、不可解释的偏好扭曲**：两只 μ 相同但 σ 不同的基金，其相对吸引力被改变的幅度取决于 σ 之差，而这个改变没有对应的投资含义。

**CAGR 仍须保留在展示层**：它是投资者理解「这些年年化赚了多少」的自然口径，也是 `08-backtest` 报告的必备指标。**能算、能展示、能进报告，只是不能进 `μ`。**

> **`Return Estimation Policy` 须显式声明 `estimate_basis = ARITHMETIC`** —— 该字段进 `estimation_policy` 版本，使「当时用的是哪个口径」可从决策快照复现。

### 5.5 Benchmark-relative Return

```
Expected Excess Return = 历史 (R_fund − R_benchmark) 的均值
```

#### 5.5.1 产出的是超额收益，必须显式还原 ⚠️

> **上游 ⑤-A 强制约束 4：**

```
Benchmark-relative 方法产出的是 Expected Excess Return，不是 Expected Absolute Return

若优化器目标函数使用绝对收益：
    必须显式还原： μ = benchmark return + expected excess return
    否则 μ'w 的金融含义不成立
```

#### 5.5.2 还原需要 Expected Benchmark Return

> **这引出一个第一阶段未解决的问题。**

```
μ = E[R_benchmark] + E[excess]

但 E[R_benchmark] 从何而来？
    · 用基准的历史均值？   → 那是另一个 Historical Mean 估计，需同样的治理
    · 用外部预测？         → 引入平台外的假设，破坏可复现性
    · 不做还原，全程用超额收益？→ 则全部约束与风险预算也须改为超额口径
```

**第一阶段的处理**：若采用本方法，**必须选择"全程超额口径"**（`Return Basis = EXCESS`），且 `Σ` 也须基于超额收益序列计算（`04` §3.3），使 `μ'w − λ/2·w'Σw` 整体在超额口径下成立。

> **不得混用** —— `μ` 用超额而 `Σ` 用绝对，是本域最隐蔽的一类错误。

`<TBD-RE2-4: 若采用 Benchmark-relative，是否全程超额口径及对约束/风险预算的影响，待投研与组合确认>`

#### 5.5.3 依赖 Benchmark Mapping 的 PIT

> 基金转型会改变其基准（`03-data/01-data-source` §5）。历史估计必须用**当时的** Benchmark Mapping，否则构成前视（`01` §8.4）。

### 5.6 Shrinkage Estimate

```
μ_shrunk = (1 − δ) × μ_sample + δ × μ_target
```

| 参数 | 说明 | 取值 |
|---|---|---|
| **`shrinkage_target`** | 收缩目标（总体均值 / 基准收益 / 零） | `TBD` |
| **`shrinkage_intensity δ`** | 收缩强度 `∈ [0, 1]` | `TBD` |

#### 5.6.1 为什么需要收缩

> **样本均值是无偏的，但方差很大。**

```
用 36 个月数据估计月度期望收益
    → 估计的标准误 ≈ σ / sqrt(36)
    → 若 σ = 5%/月，标准误 ≈ 0.83%/月 ≈ 10%/年
    → 估计误差的量级与被估计量本身相当
```

**均值-方差优化对 `μ` 的估计误差极度敏感** —— 微小的 `μ` 差异会导致权重的剧烈变化。收缩用一点偏差换取大幅的方差降低。

#### 5.6.2 收缩强度不可自行设定

> `δ = 0` 退化为样本均值，`δ = 1` 完全忽略样本信息。取值直接改变优化结果，属投资决策。

> **推荐默认 · 2026-08-27**：收缩目标 = **横截面均值**（grand mean）；收缩强度 **δ 用 James-Stein 解析式**，不设固定值。
>
> **为什么不设固定 δ**：固定值是又一个无依据的待定参数，且最优 δ 随样本量与横截面离散度变化 —— 同一个 0.3 在 60 个观测与 250 个观测下含义完全不同。解析式由数据自适应，**把一个待定参数变成一个确定的计算**。
>
> **为什么目标是横截面均值**：它表达「在没有信息区分基金时，最好的猜测是平均水平」，这与不做预测的前提一致。收缩到 0 会隐含「所有基金期望收益为零」的强假设。

## 6. Method Selection

> **不同基金是否允许使用不同方法？**

```
Method Selection Rule = TBD
```

### 6.1 若允许差异化，必须解决可比性问题 ⚠️

```
Fund A 用 Historical Mean，Fund B 用 Shrinkage
    → 两者的 μ 不在同一"估计保守度"上
    → 优化器会系统性偏好用了更激进方法的基金
```

**这不是理论顾虑** —— Shrinkage 会把高历史收益向均值拉低，未收缩的基金相对就显得更有吸引力。

**要求**：若允许方法差异化，必须在同一 `Estimation Universe` 内**保持方法一致**，或明确说明差异化的依据与其对优化的影响。

> **已定案 · 2026-08-27**：**不允许**方法差异化，全 Universe 统一使用同一估计方法。
>
> **依据**：不同方法产出的 `μ` 不在同一标尺上 —— 一只基金用历史均值、另一只用收缩后的值，两者相加得到的 `μ'w` 没有明确含义。**优化的前提是所有输入可比**，这与 §16.2 要求同 Peer Group 同一 MAR 是同一原则。
>
> **数据不足的基金不是用「更简单的方法」处理，而是 `INSUFFICIENT_DATA` 并退出本期优化** —— 换方法等于用一个不可比的数填补空缺。

### 6.2 数据可得性导致的降级同样是差异化

```
Fund C 历史不足 36M → 若自动降级为 24M 窗口
    → 这已构成方法/参数差异化
```

沿用 `01` §18.1：**不得缩短窗口凑数**，应标 `INSUFFICIENT_DATA`。

## 7. Expected Return Bounds

> **若系统需要对 `μ` 设上下界，必须由 Policy 定义。**

```
Minimum Expected Return = TBD
Maximum Expected Return = TBD
```

### 7.1 设界的动机与代价

| 动机 | 代价 |
|---|---|
| 防止极端历史收益产生不合理的 `μ` | 截断使估计有偏 |
| 避免优化器过度集中于单只基金 | **这本应由权重约束解决，而非改 `μ`** |

> **不建议用 `μ` 的界替代权重约束** —— 前者改变了估计本身（污染输入），后者是显式的组合约束（`06-portfolio/05`）。若目的是控制集中度，应使用权重上限。

> **已定案 · 2026-08-27**：设上下界 **`[μ̄ − 2σ_cross, μ̄ + 2σ_cross]`**，其中 `μ̄` 与 `σ_cross` 分别是本期横截面 `μ` 的均值与标准差；越界者截断至边界并记录 `mu_clipped = true`。
>
> **为什么需要界**：均值-方差优化对 `μ` 的极值高度敏感 —— 单只基金的估计误差可使其获得极端权重。这是马科维茨优化的已知病态，不是本系统特有的问题。
>
> **为什么用横截面自适应边界而非固定百分比**：固定值（如 ±30%）在不同市场环境下松紧完全不同 —— 牛市中 30% 不构成约束，熊市中会截断大量正常估计。**边界应随本期的横截面离散度伸缩**，这样「什么算极端」始终相对于同期同类基金而定。
>
> **截断必须留痕** —— `mu_clipped` 进入估计结果，否则无法解释「为什么这只基金的权重不如预期」。

## 8. Return Estimate Quality

### 8.1 六类质量问题

| 问题 | 处理 |
|---|---|
| **观测不足** | `INSUFFICIENT_DATA`，不缩短窗口 |
| **数据缺失** | 按 `05` §7 处理；缺失比例超阈值 → `INSUFFICIENT_DATA` |
| **极端收益** | 按 `05` §8 的异常值规则；**不得静默剔除** |
| **结构性断点** | 窗口跨越转型点 → `WARNING`（`01` §18.2） |
| **基金暂停** | 净值不更新期间的处理见 `05` §7.3 |
| **方法失败** | `ESTIMATION_FAILED`，须告警 |

### 8.2 极端收益不等于错误数据 ⚠️

```
某基金单日 +15%
  可能是数据错误（净值录入有误）
  也可能是真实的（重仓股涨停、大额赎回导致净值跳升）
```

**处理原则**（沿用 `04-factor/07-factor-validation` §5.2 的结构性/统计性区分）：

| 类型 | 判定 | 处理 |
|---|---|---|
| **结构性异常** | 违反数学定义（如收益率 < −100%） | `INVALID`，必然是数据错误 |
| **统计性异常** | 数值可能但罕见 | `WARNING`，**须核查而非直接剔除** |

> **静默剔除极端值会系统性低估风险** —— 尾部样本正是风险估计最需要的部分（`03` §9）。

## 13. Edge Cases

| 情形 | 处理 |
|---|---|
| 观测数 < 最小样本量 | `INSUFFICIENT_DATA` |
| 基金成立时长 < Lookback Window | `INSUFFICIENT_DATA`，**不缩短窗口** |
| 超额口径但 Benchmark 不可得 | `INSUFFICIENT_DATA`（整只基金不可估计） |
| 超额口径但 Benchmark Mapping 在窗口内变更 | 用各段当时的映射；跨越点标 `WARNING` |
| `μ` 为负 | **正常结果**，不做截断（除非 Policy 设界） |
| `μ` 超出 Policy 界 | 按 §7 处理，且**必须记录截断前的值** |
| 窗口内基金暂停申赎、净值不更新 | 按 `05` §7.3；连续缺失过多 → `INSUFFICIENT_DATA` |
| 窗口跨越基金转型 | `WARNING`（`01` §18.2） |
| 采用 Shrinkage 但收缩目标不可得 | `ESTIMATION_FAILED`，**不得退化为样本均值** |

### 13.1 收缩目标不可得时不得静默退化 ⚠️

```
❌ 收缩目标（同类总体均值）算不出来 → 悄悄用 δ = 0 → 退化为样本均值
   → 记录的方法是 Shrinkage，实际执行的是 Historical Mean
   → 与 06-portfolio/03 §8.2 "严禁静默降级" 是同一条原则
```

## 14. Auditability

> 本域审计总纲见 `01-estimation-framework` §19。本节只列收益估计特有的要点。

### 14.1 中间量必须保留

| 中间量 | 理由 |
|---|---|
| **样本均值**（收缩前） | 解释收缩的作用（§10.1） |
| **收缩目标值** | 同上 |
| **超额收益序列的基准值** | 超额口径下还原绝对收益所需 |
| **有效观测数** | 判断估计的可信度 |

### 14.2 方法降级或失败必须留痕

> `INSUFFICIENT_DATA` 的基金**不是"没有估计"**，而是"估计被明确判定为不可得" —— 必须记录原因，否则下游无法解释它为何未进入优化。

## 15. Summary

本域产出 `μ`，且 **`μ` 必须与 `Fund Score` 逻辑独立**。

三条来自上游的强制约束：

- **CAGR 不天然等于下一持有期的收益估计** —— 它是已实现收益率，且与算术平均的差异随波动率增大（`CAGR ≈ 算术平均 − σ²/2`）；均值-方差要求的是单期期望
- **Benchmark-relative 产出的是超额收益** —— 若优化器用绝对收益必须还原，但还原需要 `E[R_benchmark]`，而它本身又是一个待估量；第一阶段的解法是**全程超额口径**，且 `Σ` 也须基于超额序列
- **Return Basis 不可省略** —— 不记录则下游无法判断是否需要还原；`μ` 用超额而 `Σ` 用绝对是本域最隐蔽的错误

三处设计判断：

- **Simple 与 Log Return 的选择不是纯技术问题** —— 前者跨资产可加（`μ'w` 有意义），后者跨时间可加；均值-方差需要前者，且必须与 `Σ` 的定义一致
- **均值-方差对 `μ` 的估计误差极度敏感** —— 36 个月样本的年化标准误可达 10% 量级，与被估计量本身相当，这正是 Shrinkage 存在的理由
- **不建议用 `μ` 的上下界替代权重约束** —— 前者污染估计输入，后者是显式的组合约束

两条禁止：

- **静默剔除极端值会系统性低估风险** —— 尾部样本正是风险估计最需要的部分
- **收缩目标不可得时不得退化为样本均值** —— 记录的方法与实际执行的必须一致

## 16. Decisions

| # | 决策 | 理由 |
|---|---|---|
| D-1 | **不默认 `Expected Return = Historical Return`** | 后者含外推假设，需独立治理与校验 |
| D-2 | `μ` 与 `Fund Score` 逻辑独立 | 上游 §5.2 |
| D-3 | 收益率定义沿用 `03-data`，**不新建** | 避免重复定义 |
| D-4 | **Return 定义必须与 `Σ` 一致** | 否则 `μ'w` 与 `w'Σw` 处于不同收益定义下 |
| D-5 | 只实现上游 ⑤-A 登记的五种方法 | **CAPM 等未登记方法须先回上游登记** |
| D-6 | 采用 CAGR 时必须显式声明外推假设 | 上游 ⑤-A |
| D-7 | **Benchmark-relative 采用全程超额口径** | 还原需要 `E[R_benchmark]`，它本身是待估量 |
| D-8 | **`return_basis` 是必备字段** | 缺失则下游无法判断是否还原 |
| D-9 | 若允许方法差异化，须解决可比性问题 | Shrinkage 与非 Shrinkage 的保守度不同，优化器会系统性偏好后者 |
| D-10 | **不建议用 `μ` 的界替代权重约束** | 前者污染输入，后者是显式约束 |
| D-11 | **极端值须核查而非静默剔除** | 剔除尾部会系统性低估风险 |
| D-12 | **收缩目标不可得时 `ESTIMATION_FAILED`，不退化** | 与"严禁静默降级"同一原则 |
| D-13 | 收缩前后的中间值都必须保留 | 否则无法解释高历史收益基金的 `μ` 为何不高 |
