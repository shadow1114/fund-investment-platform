## 2. Method Registry

### 2.1 为什么需要注册表

> **方法不能散落在各文档的描述里。** 必须有一份可查询、可版本化、可引用的清单。

```
Estimate 记录 method_id + method_version
    → 必须能查到该版本的完整定义
    → 否则历史估计无法解释
```

### 2.2 注册项

| 字段 | 说明 |
|---|---|
| **`method_id`** | 唯一标识（如 `RE-HIST-MEAN`） |
| **`method_name`** | 名称 |
| **`method_type`** | `RETURN` / `RISK` / `CORRELATION` / `COVARIANCE` |
| **`version`** | 方法版本 |
| **`formula_ref`** | 公式定义所在文档与章节 |
| **`required_parameters`** | 该方法需要的参数清单 |
| **`applicable_horizon`** | 适用的预测期 |
| **`applicable_scope`** | 适用范围（资产类别等） |
| **`min_observation_count`** | 最小观测要求 |
| **`status`** | `DRAFT` / `ACTIVE` / `DEPRECATED` / `RETIRED` |
| `deprecation_note` | 废止原因与替代方法 |

### 2.3 第一阶段的方法清单

> **只登记上游 ⑤-A / ⑤-B 允许的方法**（`02` §5.1、`03` §5、`04` §5）。

## 3. Method Versioning

### 3.1 方法变更必须升版本，不得覆盖

```
Historical Mean V1  →  Historical Mean V2

历史估计仍引用 V1，其定义必须可查
```

### 3.2 哪些变更触发新版本

| 变更 | 级别 |
|---|---|
| **公式变更** | **Major** |
| **默认参数变更** | 见 §3.3 |
| **最小观测要求变更** | **Major** —— 改变哪些基金可估计 |
| **边界条件处理变更**（如 `σ = 0` 的处理） | **Major** |
| 补充文档说明 | Minor |

### 3.3 方法版本与参数版本必须分离 ⚠️

> **这是一处容易设计错的地方。**

```
若把参数并入方法版本：
  每次调整 λ 都产生一个新的"方法"
    → Historical Mean V1、V2、V3… 实际上公式完全相同
    → 版本号失去"公式变了"的语义

若完全分离：
  Method Version   → 公式变了
  Parameter Version → 取值变了
    → 两者组合唯一确定一次估计
```

**本域采用分离方案**：`Estimate` 同时记录 `method_version` 与 `parameter_version`（`01` §13）。

> 与 `04-factor/06-factor-versioning` 的处理不同 —— 那里参数变更升 Factor Major 版本。**差异是合理的**：Factor 的参数（如窗口）是其定义的一部分，而估计方法的参数（如 `λ`、`δ`）是可调的策略配置，调整频率高得多。

## 6. Data Preprocessing

### 6.1 预处理链

```
Raw NAV（03-data，PIT）
    ↓ ① 复权（03-data 定义）
Adjusted NAV
    ↓ ② 交易日历对齐
对齐的净值序列
    ↓ ③ 收益率计算
收益序列
    ↓ ④ 缺失处理
    ↓ ⑤ 频率聚合（若需要）
    ↓ ⑥ 异常值处理
估计用收益序列
```

> **三条支路（`μ`、`σ`、`Σ`）必须共用同一份产出**（`01` §11.1）。

### 6.2 复权规则沿用 `03-data`

> 本域**不定义**复权方式。复权方向仍是上游 `TBD-DN-3`（`03-data/05-data-normalization` §5.3），本域按后复权假设推进并显式标注，与 `04-factor/01-factor-overview` §10.1 一致。

### 6.3 交易日历对齐

| 情形 | 处理 |
|---|---|
| 基金间交易日历不同 | 取**交集**或按主日历对齐 |
| 某基金某日无净值 | 见 §7 缺失处理 |
| 跨市场基金 | 节假日错位 → §7.4 |

```
Calendar Alignment Rule = TBD
```

> **已定案 · 2026-08-27**：采用**主日历**（以基金计价市场的交易日历为准），不用交集。
>
> **依据**：
>
> ```
> 取交集：N 只基金中任一只停牌，该日即从【全体】样本中剔除
>     → Universe 越大，有效样本越少
>     → 一只问题基金可以削减所有基金的样本量
>
> 主日历：该日属交易日，个别基金无值则记为该基金的缺口
>     → 缺口影响局限在该基金自身的 data_completeness
> ```
>
> **交集法的根本问题是把个体缺陷传染给全体** —— 而缺口本就是个体属性，应由个体的完整度指标承载。
>
> **多币种场景下按 `currency` 分组各用其主日历**（与 `FR-1` 要求 Currency 进 Peer Group 划分一致）。跨币种的协方差估计须先对齐到共同交易日，此时**才**使用交集 —— 这是唯一的例外，因为协方差本就要求配对观测。

### 6.4 对齐规则直接影响相关性估计

> **取交集会减少观测数**（加剧 `04` §7.1 的高维小样本问题）；**按主日历前值填充**会人为提高相关性（填充值使两只基金在该日"同步不变"）。

**两种方式的偏差方向相反**，必须显式选择而非由实现决定。

## 7. Missing Data Treatment

### 7.1 三个层次必须区分 ⚠️

| 层次 | 含义 | 处理 |
|---|---|---|
| **Missing Observation** | 序列中的**个别缺口** | 按 §7.2 |
| **Missing Period** | **连续一段**缺失 | 按 §7.3 |
| **Insufficient History** | 历史**长度不足** | **`INSUFFICIENT_DATA`**，不可补救 |

> **三者不是程度差异，而是性质差异** —— 前两者是"有数据但有洞"，第三者是"根本没有那么长的数据"。混为一谈会导致对第三种情形做插补，那等于凭空制造历史。

### 7.2 个别缺口

| 策略 | 说明 | 代价 |
|---|---|---|
| **前值填充** | 用上一个可得净值 | 该日收益为 0，**人为降低波动率、提高相关性** |
| **跳过该日** | 从序列中删除 | 收益率跨越两日，**该点波动被高估** |
| **不处理，标记** | 交由各估计方法处理 | 各方法需各自实现 |

```
Missing Observation Strategy = TBD
```

> **已定案 · 2026-08-27**：个别缺口**不填充**，该期从收益序列中剔除并计入 `data_completeness`。
>
> **三种填充方式各自的偏差方向都是已知的**：
>
> | 填充方式 | 引入的偏差 |
> |---|---|
> | 填 0 收益 | **压低波动率** —— 人为增加零方差的观测 |
> | 向前填充净值 | 等价于填 0 收益，同上 |
> | 线性插值 | **前视** —— 用了后一期的净值 |
>
> **剔除只损失样本量，而样本量损失是可度量、可披露的**（`data_completeness`）；填充引入的偏差则会渗入全部下游统计量且无法追溯。这是「宁可少算也不错算」的一贯取舍（同 Policy ③ 对分红缺失的处理）。

### 7.3 连续缺失（暂停申赎、停牌）

> **连续缺失期间的"零收益"是虚假的。**

```
基金暂停 20 个交易日，净值不更新
  前值填充 → 20 个零收益 → 波动率被显著低估
  跳过     → 一个 20 日的累积收益点 → 该点是极端值
```

**要求**：连续缺失长度超过阈值时，该基金在该窗口的估计标 `WARNING`；超过更高阈值则 `INSUFFICIENT_DATA`。

> **已定案 · 2026-08-27**：见 `TBD-resolution-2.md` Policy E。
>
> | 判据 | 状态 |
> |---|---|
> | 连续缺失 ≤ 5 个交易日 | `VALID` |
> | 连续缺失 6~20 个交易日 | `WARNING` |
> | 连续缺失 > 20 个交易日 | `INSUFFICIENT_DATA` |
>
> **20 个交易日 ≈ 一个自然月** —— 公募基金连续一个月不披露净值属异常事件（通常是暂停估值或清盘前状态），此时序列的统计意义已不成立，而非仅仅「数据少了一些」。

### 7.4 跨市场节假日不是"缺失"

> **需要区分"数据本该有但没有"与"那天本来就不交易"。**

```
A 股基金在美股假期有净值，美股基金没有
  → 后者不是缺失，是不适用
  → 若按缺失处理并填充，会引入虚假的零收益
```

**要求**：缺失判定必须基于**该基金自身的交易日历**，而非全局日历。

## 8. Outlier Treatment

### 8.1 是否处理必须显式决定

```
Outlier Handling = TBD
```

> **本域不自行决定是否处理异常值。**

### 8.2 若处理，三项必须 Policy 驱动

| 项 | 说明 |
|---|---|
| **Detection Method** | 如 `n` 倍标准差、分位法、绝对阈值 |
| **Treatment Method** | 剔除 / 缩尾（Winsorize）/ 仅标记 |
| **Threshold** | 判定阈值 |

> **已定案 · 2026-08-27**：估计层**不做异常值处理**（不 Winsorize、不 Trim）。
>
> **依据**：**尾部正是风险估计要捕捉的对象**。
>
> ```
> 风险估计的目的：回答「最坏情况有多坏」
> Winsorize 的作用：把最坏的观测拉回到分位数边界
>     → 直接削掉了要估计的东西
>     → VaR 与 CVaR 首当其冲，波动率次之
> ```
>
> **与 `04-factor/05` `FN-3` 的一致性**：那里同样不做异常值处理，理由是分位标准化对离群值免疫。两处的理由不同但结论一致 —— 因子层是「不需要处理」，估计层是「不能处理」。
>
> **异常值仍须被识别** —— `03-data/03-data-quality` 的 `DQ-1` 会标记 Extreme Return 并告警，那是**数据质量检查**（判断是否录入错误），与**统计处理**（改变数值）是两件事。质量检查确认为真实收益后，该值原样进入估计。

### 8.3 剔除与缩尾对风险估计的影响方向相同 ⚠️

> 沿用 `03` §9：**两者都会系统性低估风险。**

```
剔除极端值   → 尾部样本消失 → σ↓、VaR↓、CVaR↓
缩尾（截断） → 尾部被压缩   → 同向影响，程度较轻
```

**尾部样本正是风险估计最需要的部分。**

### 8.4 结构性异常与统计性异常的区分是前提

> 沿用 `04-factor/07-factor-validation` §5.2、`02` §8.2、`03` §9：

| 类型 | 判定 | 处理 |
|---|---|---|
| **结构性异常** | 违反数学定义（如收益率 < −100%） | **必然是数据错误** —— 修正或剔除，留痕 |
| **统计性异常** | 数值可能但罕见 | **保留** 或按 Policy 缩尾，**须留痕** |

> **异常值处理必须逐条留痕**（`03` §16.2）—— 它直接改变风险估计，是可审计性最容易失守的地方。

## 9. Annualization

### 9.1 统一约定（已定案）

```
年化因子 A = 252 交易日
```

（P0 已定案，`02-business-requirements` §9.2.1）

### 9.2 收益与波动率的年化规则

```
年化收益（算术）   R_annual = R_period × A
年化收益（几何）   R_annual = (1 + R_period)^A − 1
年化波动率        σ_annual = σ_period × sqrt(A)
```

### 9.3 口径不一致会产生 1.20 倍的系统性错配 ⚠️

> **沿用 `04-factor/03-factor-definition` §7 的论证：**

```
若收益按 365 日历日年化、波动率按 252 交易日年化
    → Sharpe 产生约 sqrt(365/252) ≈ 1.20 倍的系统性错配
```

**全平台必须使用同一年化因子** —— 本域、`04-factor`、`06-portfolio` 不得各自选择。

### 9.4 年化不改变口径一致性要求

> **年化只是把不同频率的量换算到同一尺度，不能修复口径不一致。**

```
μ 用月频估计后年化，Σ 用日频估计后年化
    → 两者都"年化"了，但底层的样本期与观测数不同
    → 对同一时段的刻画仍不一致（01 §11.1）
```

## 10. Compounding Convention

### 10.1 算术与几何的区别

| | 算术收益 | 几何收益 |
|---|---|---|
| 计算 | 简单平均 | 复利 |
| 跨期 | 不可直接复合 | 可复合 |
| 用于 `μ` | **均值-方差要求的单期期望** | 需声明外推假设（`02` §5.3） |
| 关系 | —— | `几何 ≈ 算术 − σ²/2` |

### 10.2 必须在 Policy 中固定一种

> 混用会使 `μ` 的含义在不同基金间不一致。

> **已定案 · 2026-08-27**：复利约定 = **算术**。见 `TBD-resolution-2.md` Policy F。
>
> **依据来自 §10.1 自身的对照表** —— 「用于 `μ`：**算术** = 均值-方差要求的单期期望」。本次只是把该结论正式落案。
>
> **几何（CAGR）仍在展示层使用**，但不进 `μ`（`02-return-estimate` §5.3.1 已论证：CAGR 内含 `−σ²/2`，作 μ 会双重惩罚风险）。

## 11. Estimation Window

### 11.1 三种窗口类型

| 类型 | 说明 | 特点 |
|---|---|---|
| **Fixed Window** | 固定起止 | 不随时点移动；用于特定研究 |
| **Rolling Window** | 固定长度、随时点移动 | **最常用**；旧观测滚出 |
| **Expanding Window** | 起点固定、终点移动 | 样本持续增大；老数据权重不降 |

```
Window Type = TBD
```

### 11.2 三者对结构性断点的敏感度不同 ⚠️

```
Rolling Window：断点在若干期后滚出窗口 → 影响是【暂时的】
Expanding Window：断点永久留在样本内   → 影响是【永久的】
```

> **Expanding Window 对长历史基金意味着 10 年前的市场状态仍在影响今天的估计**，这通常不是想要的。

> **已定案 · 2026-08-27**：采用**滚动窗口**（Rolling），不用扩展窗口（Expanding）。
>
> **依据**：扩展窗口使**早期数据永久影响估计**，且影响权重随时间推移而稀释得越来越慢 ——
>
> ```
> 扩展窗口：2010 年的一次极端行情，在 2030 年仍以 1/N 的权重留在估计里
>     → 且 N 越大，新信息的边际影响越小
>     → 估计对市场状态变化的响应越来越迟钝
> ```
>
> 滚动窗口让历史影响在窗口长度之外**完全退出**，这与「估计下一期」的目标一致：更久远的市场状态与下一期的相关性已经很低。
>
> **代价是估计在窗口边界处会跳变**（一个极端观测滚出窗口时估计突变）。该代价由 `EV-2` 的稳定性告警监控，不通过改用扩展窗口来规避 —— 那是用一个持续性的偏差换取表面的平滑。

### 11.3 Lookback Window 与 Forecast Horizon 必须分开配置

> 沿用 `01` §7：**两者方向相反、含义不同，是两个独立参数。**

```
Lookback = 3Y   与   Forecast Horizon = 1Y
    → 用 3 年历史估计未来 1 年
    → 与"用 1 年历史估计未来 3 年"完全不同
```

**配置上必须是两个字段，不得合并为一个"窗口"参数。**

## 12. Parameter Governance

### 12.1 参数变更的影响必须可评估

> **参数不是"配置项"，它直接改变估计值，进而改变组合权重。**

| 变更 | 影响 |
|---|---|
| `lookback_window` 36M → 24M | 全部估计改变；短窗口对近期行情更敏感 |
| `λ` 0.94 → 0.97 | 半衰期从约 11 天变为约 23 天 |
| `δ` 0.3 → 0.5 | 相关性被压得更平，分散化看起来更好 |

**要求**：参数变更必须**升 Policy 版本并留痕**，且变更前应评估其对历史估计的影响（回溯重算对比）。

### 12.2 参数变更不改写历史估计

> 历史估计保持不变，新估计按新参数版本产生，两者通过 `parameter_version` 区分。

③ 执行预处理链（§6.1）：复权 → 对齐 → 收益率 → 缺失 → 频率 → 异常值
④ 逐步记录预处理诊断量（§15.1）
⑤ 交付统一的收益序列给 02 / 03 / 04
```

### 14.3 Output

| 字段 | 说明 |

| **`outlier_log`** | 逐条的异常值处置记录 |

| `preprocessing_rules_version` | 预处理规则版本 |

## 15. Reproducibility

```
Method Registry Version
+ Method ID + Method Version
+ Parameter Version（含单位）
+ Preprocessing Rules Version
+ Data Version
        ↓
    相同的估计
```

### 15.1 预处理规则是可复现的必要组成

> **预处理常被当作"数据准备"而不版本化，但它直接改变估计结果。**

```
对齐规则从"取交集"改为"主日历前值填充"
    → 观测数变化、相关性变化
    → 但若预处理规则未版本化，快照中无任何字段记录这次变更
```

### 16.1 预处理的每一步都要可追溯

| 步骤 | 必须记录 |

## 17. Edge Cases

| 情形 | 处理 |
|---|---|
| 方法已 `DEPRECATED` 但历史估计引用它 | 定义必须仍可查；不得删除 |
| 方法版本与参数版本不匹配（参数不适用于该方法） | **配置错误，阻断** |
| 参数缺少单位 | **不得进入生效**（§4.3） |
| 对齐后观测数低于最小要求 | `INSUFFICIENT_DATA` |
| 连续缺失超阈值 | `WARNING` 或 `INSUFFICIENT_DATA`（§7.3） |
| 跨市场基金的节假日 | 按各自交易日历判定，不视为缺失（§7.4） |
| 异常值处理后观测数显著减少 | 必须记录减少量；显著减少时标 `WARNING` |
| Expanding Window 且基金历史极长 | 老数据权重不降 → 标注局限（§11.2） |

## 18. Summary

本文档定义本域共用的方法管理与数据准备机制，**不重复各估计量的公式**。

三条设计判断：

- **方法版本与参数版本必须分离** —— 否则每次调 `λ` 都产生一个公式相同的"新方法"，版本号失去语义；这与 `04-factor` 的处理不同，差异是合理的（Factor 的窗口是定义的一部分，估计方法的 `λ` 是可调配置）
- **参数的单位不可省略** —— `lookback_window = 36` 是 36 个月还是 36 个交易日，`confidence_level = 95` 是 95% 还是 0.95，歧义会造成隐蔽错误
- **Lookback Window 与 Forecast Horizon 必须是两个字段** —— 不得合并为一个"窗口"参数

三处预处理的方向性影响：

- **对齐规则的两种方式偏差方向相反** —— 取交集减少观测数（加剧高维小样本），前值填充人为提高相关性
- **缺失数据的三个层次是性质差异而非程度差异** —— 对"历史长度不足"做插补等于凭空制造历史
- **剔除与缩尾对风险估计的影响同向** —— 两者都系统性低估风险；尾部样本正是最需要的部分

两处容易被忽略的治理要求：

- **跨市场节假日不是缺失** —— 缺失判定必须基于该基金自身的交易日历，否则会引入虚假的零收益
- **预处理规则必须版本化** —— 它常被当作"数据准备"，但对齐方式的改变会直接改变相关性估计，不版本化则快照中无任何记录

## 19. Decisions

| # | 决策 | 理由 |
|---|---|---|
| D-1 | 建立 Method Registry | 历史估计必须能查到当时方法的完整定义 |
| D-2 | **只注册上游已登记的方法** | 上游文档协议第 3 条 |
| D-3 | **方法版本与参数版本分离** | 否则版本号失去"公式变了"的语义 |
| D-4 | 与 `04-factor` 的版本处理差异是**有意的** | Factor 参数是定义的一部分，估计参数是可调配置 |
| D-5 | **参数必须显式声明单位** | 单位歧义是隐蔽错误来源 |
| D-6 | 单位变更等同取值变更 | 同上 |
| D-7 | **数据可得性导致的降级是"失败"而非"选择"** | 否则口径不一致且污染 `Σ` |
| D-8 | 复权规则沿用 `03-data`，本域不定义 | 避免重复定义 |
| D-9 | **对齐规则必须显式选择** | 两种方式偏差方向相反 |
| D-10 | **缺失数据三层次严格区分** | 对"长度不足"插补等于制造历史 |
| D-11 | **跨市场节假日不视为缺失** | 按各基金自身日历判定 |
| D-12 | 异常值处理必须逐条留痕 | 直接改变风险估计 |
| D-13 | **年化因子全平台统一 252** | 口径不一致产生 1.20 倍错配 |
| D-14 | **Lookback 与 Horizon 必须是两个字段** | 方向相反、含义不同 |
| D-15 | **预处理规则必须版本化** | 对齐方式改变会改变相关性估计 |
