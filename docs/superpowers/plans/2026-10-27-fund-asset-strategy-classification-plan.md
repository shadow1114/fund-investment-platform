# 基金资产类别与投资策略分类实施计划

> 日期：2026-10-27 ｜状态：实施基准（分类功能采用唯一当前规则）

> 当前开发约定：分类只保留一套当前规则，直接覆盖原分类入口；不提供规则/枚举版本字段、并行配置或规则升级操作。分类修订序号只用于审计和 PIT 查询。

## 1. 目标与依据

将本轮基金分类工作聚焦于 **`asset_class` 和 `strategy`**，暂时停止其他三个维度的自动提取、裁决和新增复核。资产类别沿用最新证据完善计划，投资策略采用指定策略计划，并结合现有系统的修订、PIT 和人工复核机制落地。

依据及适用关系：

| 依据 | 本文采用内容 |
|---|---|
| 产品上游 v2.6 | Fund Classification 属于 Fund Data；纯 Quant；PIT、修订留存、可复现；不改变十个 Stage |
| `/Users/szld2403280/.claude/plans/elegant-stargazing-wolf.md`，《五维分类证据提取完善计划》 | 资产类型白名单、原始观察与派生证据分离、精确指数目录、刷新替换、冲突与人工保护 |
| 历史策略分类计划 | 指数集合优先、目标日期/目标风险/主动规则、独立量化标签、雪球详情、基准辅助 |
| 当前分类实现 | 已实现的观察/提取/修订/复核基础；作为实施起点，而非另建分类系统 |

**不在范围内：** `geography`、`product_structure`、`market_attributes` 的来源增强；同花顺结构资料、ETF/LOF 名录；AI/ML/LLM；评分、Peer Group、组合或交易策略重设计；新增基金导入能力；自动全库重分类。此前撤销的 product_structure 来源增强不重新纳入。

## 2. 本轮固定决策

1. 活跃分类维度仅为 `asset_class`、`strategy`；`strategy_tags` 是策略附属标签，不是新的互斥主策略，也不是第六个核心分类维度。
2. 主策略为 `ACTIVE / PASSIVE_INDEX / ENHANCED_INDEX / TARGET_DATE / TARGET_RISK / UNKNOWN`。
3. `QUANTITATIVE` 从主策略移出，成为可与任何主策略并存的标签。标签证据充分时，主策略仍可为 UNKNOWN。
4. 名称只生成候选；缺失、未命中或否定不能反向证明 ACTIVE。
5. 真实可靠矛盾进入 CONFLICT；规则优先级不能吞掉矛盾。
6. 复用已有 Observation、Evidence、ClassificationSnapshot、不可变修订、PIT、复核与审计，不另建平行 `fund_strategy_classification` 事实体系。
7. 以唯一当前规则覆盖原分类入口。现存快照保留只读供审计，运行时不按规则/枚举标识分流。
8. 数据采集与纯分类分离；分类引擎不直接调用 AKShare。

## 3. 两维聚焦与暂停维度兼容

### 3.1 自动处理范围

新版配置显式声明 `active_dimensions=[asset_class, strategy]`，标签引擎独立执行。不能仅在 UI 隐藏三个维度、后台仍继续更新和创建复核。

- 暂停维度的原始资料可以继续归档，但本轮不生成新的自动分类断言。
- 从正式类型提取资产时，不再顺便更新 QDII/跨境属性；从真实跟踪指数提取资产时，不再更新地域。
- 历史修订、观察、证据和人工决定不删除；历史 API 保持按原修订读取。
- 当前读模型标记暂停维度 `evaluation_state=PAUSED`，新基金没有历史结果时为 `NOT_EVALUATED`，避免把“未计算”误解为“已计算但无法识别”。这两个标记不替代现有四种分类状态。
- 新基金为兼容五维快照可保留空 UNKNOWN 占位，但必须带 NOT_EVALUATED 元数据，不进入 UNKNOWN 质量统计或复核队列。
- 已有暂停维度结果标记为历史保留，不宣传为本轮重新验证；不默认参与当前准入或 Peer Group 规则。依赖这些维度的消费者必须显式选择历史结果，或提示所需分类未更新，不能静默忽略约束。

### 3.2 暂停维度历史处理

当前规则只计算资产类别和投资策略。暂停维度的历史结果原样保留，通过 `carried_from_revision_id` 标记来源及 PAUSED 状态；不重新提取，不伪造新审核。

对于历史目录中不能无损装入当前目录的结果：

- 原快照完整保留，并通过暂停维度来源引用供历史展示；禁止把旧编码混写进新版有效分类字段。
- 当前对应字段为 NOT_EVALUATED 空占位，UI 单独显示历史保留结果，不把它映射为新编码。
- 若下游仍要求这些旧字段，继续读取历史修订，不能将当前占位当作一次事实撤销。

此兼容机制只服务历史审计，不提供用户可选的分类规则集。

## 4. 数据来源与采集契约

### 4.1 来源分工

| 来源 | 使用内容 | 使用边界 |
|---|---|---|
| `fund_name_em()` | 六位代码、简称、正式类型 | 复用基金列表采集；正式类型用于资产；名称仅候选 |
| 既有基金概况 | 类型、真实跟踪标的及实际返回的可选字段 | 不假定一定含投资策略、目标或底层资产 |
| `fund_info_index_em(symbol="全部", indicator="被动指数型")` | 被动指数集合成员身份 | 用代码和请求参数证明 membership，不证明具体跟踪指数或资产类别 |
| `fund_info_index_em(symbol="全部", indicator="增强指数型")` | 增强指数集合成员身份 | 同上；与被动集合共同形成第一轮策略输入 |
| `fund_individual_basic_info_xq(symbol=fund_code, timeout=...)` | 基金类型、投资策略、投资目标、业绩比较基准 | 新接入长表资料，按需获取；空值与缺字段分开处理 |
| 受控真实指数目录 | 指数身份、别名、底层资产及依据 | 仅精确匹配实际 tracking_target；不从 benchmark 或列表查询类别冒充跟踪标的 |

AKShare 是访问适配器；证据需同时记录实际来源平台、dataset、函数/endpoint、参数、载荷和字段定位。东方财富、雪球资料标记 AGGREGATOR，不因字段内容像正式资料而提升为 OFFICIAL。

### 4.2 本地源码核对结果与风险

本轮只读核对了本地安装的 AKShare 源码，**未执行联网验证**：

- `fund_info_index_em` 支持 `symbol="全部"`，两种 indicator 对应不同请求过滤条件。
- 返回的 `跟踪标的` 是函数赋值的 `symbol`，`跟踪方式` 是函数赋值的 `indicator`。它们是查询上下文，不是逐基金披露事实。
- 因此 `跟踪标的="全部"/"股票指数"/"债券指数"` 必须隔离为查询元数据，不能送入真实指数提取器。
- 本地实现请求固定第一页、`pn=10000`，不能据此宣称覆盖所有基金或列表完整；需要记录行数、集合批次、覆盖质量及截断风险。
- 指数函数未暴露 timeout 参数；采集应复用受控隔离调用和硬超时，不在主 Worker 无期限等待。
- 雪球函数返回 `item/value` 长表，实际 item 包含中文“基金类型”“投资策略”“投资目标”“业绩比较基准”；不是参考计划示例中的英文宽表。
- 雪球本地实现对若干字段直接选列；上游缺字段可能导致异常。适配器必须留诊断并报告契约失败，不能将异常解释为资料明确为空。

### 4.3 集中获取与按需补充

1. 集中获取/读取基金列表与两类指数集合，避免每只基金重复下载整个名单。
2. 通过 `ProviderFundIdentity → FundShareClass → Fund` 解析代码；不按名称或代码前缀合并产品。
3. 基于成功载荷执行第一轮资产/策略分类。
4. 对主策略未确定、冲突需核验、资料过期或标签尚未评估的基金，按需补充雪球资料。
5. **指数主策略已确定也不能跳过标签评估。** 已有可靠策略文本可离线提取标签，否则按需获取详情，或明确显示标签 NOT_EVALUATED。
6. 第二轮合并有效观察，执行两维裁决与标签引擎，写修订或复核提案。

两类指数名单各自保存成功快照与来源时间，联合分类记录两边 payload 引用和新鲜度。某一侧失败时保留旧证据并提示来源失败；不能以另一个集合成功来假定失败集合为空或“该基金不在其中”。

成功完整名单可撤销该来源上一批次的成员观察，但必须明确批次覆盖范围并通过完整性检查。截断、疑似异常空集、解析错误或缺列只留诊断，不批量清空。移出集合只撤销该集合的正向断言，**不产生 ACTIVE 或非指数断言**。

## 5. Asset Class 规则

### 5.1 枚举与证据

枚举保持：`EQUITY / BOND / MIXED / MONEY_MARKET / FOF / REIT / COMMODITY / OTHER / UNKNOWN`。

可确认依据：正式类型精确白名单；明确底层资产分类资料；真实 tracking_target 精确命中指数目录。名称、泛化关键词、可投资范围只能辅助或候选。

- 正式类型与指数底层资产给出不同可靠类别：CONFLICT，保留双方证据。
- 未知正式类型保留原文并生成稳定去重复核项；即使其他依据确认资产，也不能丢失未识别类型问题。
- 未知/歧义/复合跟踪标的不做模糊确认，不把复合指数简化成其中一个资产。
- benchmark 不进入资产确认路径；“允许投资股票”不证明 EQUITY。
- `OTHER` 需要明确受控类型依据，不是所有未知类型的兜底。

## 6. Strategy 主策略规则

### 6.1 规则表

| 优先级 | 规则 | 正向条件 | 主策略 |
|---|---|---|---|
| 100 | STR001 | 有效增强指数集合 membership | ENHANCED_INDEX |
| 90 | STR002 | 有效被动指数集合 membership | PASSIVE_INDEX |
| 80 | STR010 | 正式类型/策略/目标明确采用目标日期策略 | TARGET_DATE |
| 70 | STR020 | 正式类型/策略/目标明确采用目标风险策略或受控目标风险机制 | TARGET_RISK |
| 60 | STR030 | 可靠非指数类型 + 明确主动管理策略，且无已确认专属主策略 | ACTIVE |
| 0 | STR999 | 无充分正向证据 | UNKNOWN |

优先级用于规则执行顺序及复核建议，不用于压过真实互斥事实。所有规则输出保存来源、命中片段和观察引用。

### 6.2 指数集合及冲突

参考策略文档同时存在“双集合命中增强优先”和“双集合命中进入 CONFLICT”的表述，本文统一为：

- 只命中增强集合且无可靠矛盾：确认 ENHANCED_INDEX。
- 只命中被动集合且无可靠矛盾：确认 PASSIVE_INDEX。
- 同时命中两集合：`strategy.status=CONFLICT`，保留两种候选，复核建议 ENHANCED_INDEX；**不能把建议值作为 CONFIRMED 对外消费**。
- 集合与正式策略独立可靠声明互斥：CONFLICT；来源等级或数字优先级不得静默覆盖。
- 名称候选与可靠集合不同：名称不构成同等级事实冲突，但保存线索及解释。

已有正式策略文本仍可补充明确被动复制/指数增强依据。复制规则需要指数语境；“复制某组合”不等于被动指数。同句“通过复制指数并主动增强”属于增强实现手段，不拆为被动与主动两条主策略；独立明确互斥声明不得被此规则隐藏。

### 6.3 目标日期、目标风险

- 目标日期须有正式类型、策略或目标中的明确正向声明；名称年份或“养老”字样不够。
- 目标风险须有明确目标风险策略或经配置登记的机制；泛“控制风险”“稳健”“风险收益匹配”不够。
- 同时有不兼容目标日期/目标风险正式依据：CONFLICT，不能以优先级强选。
- 目标基金底层管理采用主动方法，不自动使其主策略变为 ACTIVE；其量化方法可另打标签。

### 6.4 ACTIVE 的保守识别

STR030 是多观察联合规则，不能只靠 `extract_observation()` 对一个关键词作裁决：

1. 正式类型在受控“可作为非指数依据”的类型集合中；未知类型、泛指数型、名单未命中均不算此依据。
2. 投资策略明确描述基金实际采用主动管理，或满足登记的主动机制组合规则。
3. 无被动/增强指数或目标日期/风险的已确认专属策略；可靠互斥证据应冲突，而不是当作普通排除后丢失。

“主动管理/主动投资”须明确指基金主投资机制；“精选/优选/基本面研究/自上而下/自下而上”单独出现不确认 ACTIVE。增强基金局部主动增强、被动基金现金头寸管理，不另确认 ACTIVE。

“无跟踪标的”“不是被动”“未命中指数名单”均不能兜底 ACTIVE。纯债、货币、混合或 FOF 类型也不能单独证明主动策略。

### 6.5 文本语境

保留现有否定、条件、引用过滤，并为新规则增加正反例：明确采用才产生正向断言；“不采用量化”“可采用多因子”“其他基金使用目标风险”等不确认对应结论。原文独立保留，不将字段拼成无法定位的单一文本；联合规则证据必须关联全部必要观察。

## 7. 独立 Strategy Tags

当前标签目录仅含 `QUANTITATIVE`；扩展时直接更新唯一当前目录和校验规则。

- 投资策略明确采用量化模型、多因子、因子模型、数量化等受控方法：标签 CONFIRMED。
- 名称出现“量化”：仅标签 CANDIDATE，不放进已确认标签数组。
- 否定、可选方法、引用：不确认标签；明确否定与正向可靠证据矛盾时为标签 CONFLICT，进入复核。
- 主策略与标签独立裁决：ACTIVE、ENHANCED_INDEX、PASSIVE_INDEX 等可以带 QUANTITATIVE；标签不能反推 ACTIVE。
- 未获取策略资料不代表“非量化”；标签为空必须结合评估状态解释。

快照中新增有证据的标签结果，例如 `strategy_tag_results` 保存各标签状态、候选、证据及评估状态；API 的 `strategy_tags` 仅投影 CONFIRMED 标签。缺乏证据的状态为 UNKNOWN；独立 `evaluation_state` 区分 NOT_EVALUATED 与 EVALUATED。不能只持久化无证据的字符串数组。

人工决定支持确认/拒绝标签，拒绝有审计记录；后续自动刷新不能自动重新加回。标签变更参与提案去重、语义 hash、历史修订和 PIT。

## 8. Benchmark 与证据等级

benchmark 仅保留为辅助核验资料，不单独决定资产、策略、量化标签或真实跟踪指数。

- 主动基金使用沪深300作为基准，不是策略冲突。
- 被动基金使用“权益指数 + 现金”复合基准，不因不是纯指数基准而冲突。
- 若核验规则发现明确不一致，生成有规则依据的复核提示；benchmark 文本本身不生成互斥策略断言。
- 不改变上游 Fund Benchmark 的选择层级，不在本轮做 Benchmark Classification。

参考策略计划的 HIGH/MEDIUM/LOW 表示建议证据强度，不直接替换当前 `OFFICIAL_DOCUMENT / PUBLIC_AGGREGATOR / NAME_HINT` 来源等级，也不解释为概率。现有 confidence 编码继续使用；规则充分性通过 assertion、status、rule_id 和 review_items 表达。自动 CONFIRMED 不等于人工 reviewed，不引入会冒充人工批准的 AUTO_APPROVED 状态。

## 9. Observation、刷新与持久化

复用现有观察替换逻辑，新增指数 membership 与雪球适配：

- 身份包含实际 provider/dataset、Fund + 来源份额代码、稳定请求参数、原始字段及必要行标识；不含 payload ID、采集时间或提取时间。
- membership 的 indicator 必须参与身份，不能将增强和被动集合观察互相覆盖。保留查询类别为元数据，不使用误导性 tracking_target 字段别名。
- 明确空值/不适用撤销同一观察的自动派生证据；未返回字段按 dataset 覆盖契约处理，不默认清空。
- 部分刷新只替换对应来源/字段；失败不撤销有效资料；旧有效资料的时间和失败诊断必须可见。
- 相同语义重复采集不增加修订；分类状态、值或标签发生变化时产生修订或提案。
- 语义 hash 排除时间、载荷定位和生成 ID，包含必要观察关系、活跃维度、标签、暂停元数据与来源修订引用，确定性排序。
- Fund 产品层汇总真实份额来源，不覆盖不同份额观察；映射未确认时显式报告，不自动合并同名产品。

已审核基线遇到自动新资料，沿用 `NEW_EVIDENCE_AFTER_REVIEW`，不覆盖人工决定。持续保留待审观察参与下一次提案重算；相同提案不重复建案。继续使用产品锁、外层事务、CAS 和审计。

PIT 严格使用 `available_at ≤ decision_at`；先选最大可见修订序号，再选适用业务区间。按上游 v2.6 保留/解析 published_at、provider_available_at、ingested_at 及 availability_quality。没有可靠披露时间时不伪造历史时间；今天抓到的名单不代表基金成立时已经可用。当前规则重放写入本次真实可用的新修订，旧 decision_at 查询结果不变。

## 10. 唯一规则与人工复核

### 10.1 当前规则与历史读取

分类策略统一保存在 `current.yaml`，不保留多份可选规则配置。主策略移除 QUANTITATIVE，新增独立标签目录、当前活跃范围和来源规则配置。

- 历史快照缺少标签/评估元数据时仍可读取，按历史记录原样展示；标签默认“历史记录未提供”，不推断为空且已评估。
- 旧 `strategy=QUANTITATIVE` 不自动映射为 ACTIVE。新版从原始观察重算主策略与标签；无充分主策略证据则 UNKNOWN。
- 不把旧最终策略编码当作新的正式原始资料；历史人工决定仍是历史决定，不冒充新观察。
- catalog、筛选、API 验证和复核均使用唯一当前规则；不按快照携带规则标识分流。

### 10.2 分类复核

复核直接应用唯一当前规则，不提供升级/拒绝升级控制：

1. 继续 CAS 校验 expected_revision。
2. 必须确认本轮两维及发生变化的标签决定；即使资产编码相同，也明确确认保留。
3. 暂停维度按 §3 的兼容规则保留或引用历史，不要求重新裁决，不得借此提交修改暂停维度的决定。
4. 标签决定采用独立受校验结构，不能把主策略 ReviewDecision 原样套到多标签集合。
5. 保留复核前后快照、人工 action/value、理由和操作者。

暂停维度产生的旧待审案例不删除；标记为历史/暂停，默认队列不催促处理。混合案例显示来源维度，新流程仅对活跃范围生成决定，不静默关闭未处理历史事项。

### 10.3 旧评价投影保护

`project_legacy()` 及所有分类消费者必须显式评估新版影响：

- 主策略和资产仅 CONFIRMED 时参与旧画像投影。
- ENHANCED_INDEX、UNKNOWN、CONFLICT 不硬塞 ACTIVE_EQUITY/PASSIVE_EQUITY。
- 原先 QUANTITATIVE 主策略可能被旧投影排除；改为 ACTIVE + QUANTITATIVE 后不能未经决策就突然纳入旧主动组。
- 本轮保守维持该准入边界：当前规则确认量化标签的权益基金不自动新增到旧 ACTIVE_EQUITY 投影；后续如需准入，直接调整当前评价政策。
- 标签尚未评估不能作为“非量化”证明；旧量化基线相关升级在标签核验完成前不得因 UNKNOWN 主策略/标签变化悄悄扩大准入。

分类变更不得反向由 Fund Score 或 Fund Universe 决定；Peer Group 仍独立于 Score。

## 11. API、前端、CLI 与 Worker

### API / 前端

- catalog 暴露 active_dimensions、paused_dimensions 和 strategy_tags 目录；不提供规则/枚举标识选择。
- 分类响应包含两维结果、标签详情/确认标签数组、暂停说明及历史来源引用。
- 默认基金筛选和复核页面聚焦两维与标签；历史三个维度保留只读展开。
- 标签筛选仅匹配 CONFIRMED；策略 CONFLICT 或 CANDIDATE 不当作已确认值匹配。
- 分类筛选使用唯一当前目录。历史 QUANTITATIVE 主策略不隐式等同当前 QUANTITATIVE 标签。
- 复核页面分别显示 baseline/incoming 字典、双集合冲突、联合规则证据和标签决定。
- 同步冻结 OpenAPI 后使用 `npm --prefix frontend run api:generate`，不手改 Orval 生成文件。

### CLI / Worker

- `classify-funds` 只重放保存资料，不隐式联网；默认统计活跃两维和标签，排除暂停占位。
- `refresh-classification` 扩展为明确的来源刷新编排，复用已有概况，并按需补充雪球；两类指数集合集中刷新，不在单基金循环里下载。
- 新增集中指数集合刷新入口及参数，确切命令名在实施时与现有 CLI 风格对齐；不增加 extract/全库重分类 HTTP API。
- BASIC_INFO 及来源补充继续使用独立 CalculationJob Worker；不改用 FastAPI BackgroundTasks。
- 来源独立超时、限速、重试、诊断与部分成功报告；沿用已有受控机制，隔离任务超时后必须终止子进程。
- dry-run 分类走与正式执行相同的纯提取/裁决路径但不写业务修订；联网刷新 dry-run 仅显示拟请求，不偷偷发起网络请求。
- 预览显示两维、标签、修订变化、暂停保留、来源新鲜度、未识别原因与 `NO_CHANGE / WRITE_REVISION / CREATE_REVIEW`。

## 13. 测试、验收与发布边界

### 13.1 离线规则与来源测试

- 27正式类型参数化回归，包括混合型-灵活=MIXED、混合一级/二级债券=BOND、三类受控 UNKNOWN。
- 类型与真实指数资产矛盾；未知、复合标的；benchmark 不确认资产。
- 指数接口“跟踪标的=全部/股票指数/债券指数”不生成真实指数资产断言。
- 每条 STR 规则正反例；双集合、正式文本冲突；同句增强复制与独立矛盾。
- ACTIVE 的类型+策略联合条件；名称、无标的、名单未命中、单关键词不能确认。
- 目标年份/泛风险、否定/条件/引用不能确认专属策略。
- ACTIVE/ENHANCED_INDEX/PASSIVE_INDEX + QUANTITATIVE；仅标签可确认而主策略 UNKNOWN；名称标签候选、未评估与拒绝标签。
- 雪球 item/value 转换、重复项/代码不一致/缺列/空值；指数前导零、错误代码、空集、截断、部分失败和完整批次撤销。
- 自动资料不得生成暂停维度断言或新增暂停复核。

### 13.2 兼容、刷新与链路测试

- 旧 JSON 无新增字段可读取；1.0/2.0 catalog 原样，旧 QUANTITATIVE 不自动变 ACTIVE。
- 暂停维度保留、历史修订引用、不兼容编码不混写；新基金 NOT_EVALUATED 不计 UNKNOWN 率。
- 两维升级审核、标签人工决定、CAS/权限、人工保护、提案去重。
- 部分更新与显式空值；失败保留；membership 移出不是 ACTIVE；不同份额/来源参数不互相覆盖。
- 语义相同不增修订；标签变化可产生新修订；available_at 不倒填；旧 decision_at 结果一致。
- 旧量化投影边界不意外扩大；依赖暂停维度的消费者显式处理。
- API/冻结 OpenAPI/Orval 类型一致；复核页面 baseline/incoming；筛选只取确认结果；CLI dry-run 不写/不联网。

### 13.3 人工样本与完成标准

后续建立带真实来源、采集时间和人工核验记录的 Golden Dataset；各主策略目标抽取约30–50只，另覆盖量化标签与冲突/未知。这是待执行验收工作，不是已经完成的数据集；不能编造核验结果或精度指标。

完成标准：

1. 两维自动分类与独立标签完整贯通，暂停三个维度且历史可追溯。
2. 每个确认/候选/冲突结论能回溯规则、必要输入观察和载荷；自动确认不冒充人工审核。
3. 相同输入的分类结果确定性一致；未命中不兜底错误确认。
4. 历史修订、PIT、人工决定与旧画像边界回归通过。
5. 离线规则/来源/API/前端测试及静态检查通过；授权隔离库中的修订/审核/Worker 验证通过。
6. 真实样本人工核验通过后，先小批 dry-run 查看差异，经明确授权落库；不自动全库刷新。

### 13.4 操作安全

本轮代码按唯一当前规则覆盖原有分类入口，并新增数据库迁移以合并分类方案标识、移除分类规则/枚举版本列。迁移已应用到授权的 `fip_test`，其当前 head 为 0038；未对开发或生产库迁移，也未执行联网采集或数据刷新。

`tests/conftest.py` 的数据库 fixture 会删除重建业务及 public schema 并迁移，**必须先明确确认目标是可丢弃隔离测试库**；不得在开发/生产库运行。真实网络验证、批量落库和全库刷新需按既有采集流程执行；不读取或输出 `.env` 秘密，不删业务数据，不自动提交或推送 Git。
